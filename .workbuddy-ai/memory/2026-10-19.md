## Redis 缓存节点部署（服务器 122.228.216.138）
- 目标：为官网 + 客户端 API 提供高并发缓存层。主机 Debian 12、宝塔面板、2 vCPU / 1.9 GB RAM，此前无任何站点/数据库代码，是空白全新机器。
- 安装 Redis 7.0.15（apt 官方源），systemd 托管并开机自启。
- 关键配置：`maxmemory 384mb` + `allkeys-lru`、`bind 0.0.0.0` + `protected-mode yes` + 40 位 `requirepass`、`appendonly no`（纯缓存定位，存队列需改为 yes）、`save 900 1/300 10`、`FLUSHALL/FLUSHDB/DEBUG` 已 rename 禁用、`maxclients 10000`。
- 内核/系统层：`vm.overcommit_memory=1`、`somaxconn=8192`、`swappiness=1`、关闭 THP（disable-thp.service）、新增 2 GB swap（原机无 swap）、UFW 放行 6379。
- 实测：本地回环 SET/GET pipeline 约 46 万 QPS；200 并发 ~78 万→59–78 万 QPS；延迟平均 0.12 ms；公网访问 + 密码认证 + 禁用命令均验证通过。
- **遗留风险**：6379 当前对全网开放（仅密码防护）；公网 RTT 约 85 ms，若应用服务器在国内会有明显延迟收益折损——已写入报告建议用户收紧 IP 白名单并确认同区域部署。
- 交付物：outputs/redis_deployment_report.md、outputs/etc_redis_redis.conf、outputs/redis-server.service.d_override.conf

### 该宝塔机器的 4 个环境缺陷（下次部署同型机器直接参考）
1. Debian 包的 `/usr/bin/redis-server` 是指回 `redis-check-rdb` 的符号链接，unit 的 `NoExecPaths=/` 白名单只认真实路径 → exit 127。**修复：用 redis-check-rdb 的副本替换该符号链接**。
2. `libjemalloc.so.2` 位于 `/usr/local/lib`（宝塔自建 jemalloc，经 ld.so.conf 优先），不在 ExecPaths 白名单 → `failed to map segment from shared object`。**修复：drop-in 追加 `ExecPaths=/usr/local/lib`**。
3. 配置了 unix socket 但 RuntimeDirectory 目录未生成 → 启动失败。**最终移除 unixsocket，走 TCP**。
4. 日志文件由 root 测试进程创建，redis 用户不可写 → 启动后无日志直接退出。**修复：`chown redis:redis /var/log/redis`**。
- 运维提示：`pkill -f redis-server` 会匹配到 SSH 命令自身导致会话被杀，`ufw` 与宝塔面板防火墙非同一套。

### 两个真 bug（都会让功能看起来"没反应"）

1. **`QLinearGradient` 未在模块级 QtGui 导入** → paintEvent NameError；

   静默退出、退出码 127。排查手法：子类包一层 try/except 打印 super() 的异常。
2. **`amp = max(1.0, min(1.0, shape)) * lv` 恒等于 lv**（max(1.0,…) 抵消了钳制）→
   所有条形等高，相位动画失效；加上 shape 的 0.34 地板，0.15 与 1.0 音量只差 7px。
   修后：去地板 + `min(1.0, shape)`，实测条形最高 2px→8px→17px（低/中/高音量），全量程响应。
