## 修复：积分为 0 仍可进行简短对话

**根因**：内置模型（agens）的积分扣费是「流式输出攒够 `TOKEN_FLUSH_THRESHOLD`(100) token

所以 0 积分用户能白聊约 100 token 才被截断（截图现象：余额 0 但对话继续）。

- 新增 `_builtin_points_gate(auth)`：读本地缓存余额（WS `points_update` 与每次扣费响应刷新），
  `<= 0` 返回提示文案，放行返回空串；取余额异常不阻断（交给扣费环节 402 兜底）。
- `_run_inner` 在创建 `PointsConsumer` 之前调用它，命中即以「积分不足」结束任务并 return，
  不再发出任何 LLM 请求。`_run_inner` 是引擎唯一入口（子 Agent / 后台任务都走它），无旁路。

## 修复：窗口折叠动画三个 bug（最小化卡顿/假动画/重复播放、最大化按钮假死、折叠拖影）

**文件**：`src/zhuzhu_Copilot/ui/window_fx.py`、`src/zhuzhu_Copilot/ui/agent_panel.py`

1. **最小化卡顿 + 不播动画 + 重复播放**
   - 根因 A：`showMinimized()` 在精灵图创建**之前**执行——窗口先消失约 70ms，用户看到的是
     「窗口没了→动画才出现」，观感即「没播动画直接最小化」，随后全尺寸快照又「重播」一次。
   - 修复：`start_conceal` 把 `showMinimized()` 挪进 `_play(before=_minimize)` 回调，
     **精灵先盖住窗口再执行（阻塞式的）最小化**；`before` 返回失败即 `cancel()`。
   - 根因 B：动画播放中到达的重复 `WM_SYSCOMMAND`/按钮点击。原 `can_conceal()` 返回 False →
     消息继续下发给原生窗口 → 原生最小化把正在跑的折叠直接掐断。
     修复：`can_conceal()/can_reveal()` 在 `_busy` 时**一律返回 True**（吞掉重复命令），
     同时 `TaskbarCommandFilter` 加 0.3s 去重（Qt 会经 `windows_generic_MSG` 与
     `windows_dispatcher_MSG` 两条路径重复投递同一条消息，`_last_key/_last_at`）。
2. **连点最大化/恢复正常大小 → 假死**
   - 根因 A：动画期间的额外点击穿透到原生 `showMaximized()/showNormal()`，与正在跑的形变互斗；
   - 根因 B：每次点击都要等面板整体重排，主线程单次阻塞 137~672ms，连续点击叠加成假死；
   - 根因 C：`setWindowState(WindowNoState)` **不会恢复几何**，窗口停在「全屏尺寸但未 zoomed」
     的坏状态（实测 rect 1920×1032 / IsZoomed=0），此后按钮彻底失效。
   - 修复：`agent_panel._toggle_max_restore` 在 `self._fx.busy()` 时直接 return；
     新增 `window_fx.unmaximize(win, target)`：`setWindowState(NoState)` → 兜底 `showNormal()`
     → `setGeometry(target)` 三连，`start_restore_size` 传 `before=lambda: unmaximize(w, QRect(end))`。
   - 实测 10 次连点：只触发 2 次形变，终态健康，无残留精灵。
3. **折叠拖影**
   - 根因：`FoldSprite.paintEvent` 只画当前帧，不清脏区。分层窗口（`WA_TranslucentBackground`）
     **背面缓冲不会自动擦除**，而折叠是「内容矩形逐帧收缩」，腾空区域残留上一帧大矩形 → 拖影。
   - 修复：绘制前 `p.setCompositionMode(CompositionMode_Clear)` + `fillRect(e.rect())`，
     再切回 `SourceOver`。进程内用 `render()` 累积到共享 pixmap 验证：旧实现 alpha=255（拖影），
     新实现 vacated 区 alpha=0。

**其他配套改动**
- `set_transitions(win, disabled)`：动画期间用 `DWMWA_TRANSITIONS_FORCEDISABLED` 关掉 DWM 自己的
  最小化/还原过渡，避免和我们的精灵叠加。实测本机 DWM 最小化动画未生效（A/B 无差异），
  仅作无害保险。
- 精灵复用池 `_spare`：避免每次动画 ~30ms 的原生窗口创建开销（实测 show 1~4ms）。
- `_restore_window` 末尾 `w.repaint()`：防止精灵退场瞬间露出桌面（还原闪白）。
- `recently_restored(0.7s)`：`changeEvent` 里阻止面板回弹动画叠在折叠揭示之上。
- `showEvent` 预热延迟 1200ms → 600ms。
- `unmaximize` 里 `win.geometry() != target` 才 `setGeometry`，避免无谓重排。

**调试手段备忘（排错时很有用）**
- `FoldSprite` 与主窗口同标题，探测脚本要用 `exstyle & 0x080800A8 == 0x080800A8` 过滤。
- 跨进程 `SendMessage(WM_SYSCOMMAND)` **到不了** Qt 的 native event filter，模拟要用 `PostMessage`。
- 屏幕 `BitBlt` 读回约 70ms/帧，追不上 230ms 的动画；验证逐帧内容要在进程内用 `render()`。

## 终验结论与 `_dbg` 日志语义（2026-10-23 上午补）

**FX 调试日志字段含义（之前理解错过，纠正）**
`_dbg("filter ... min=%s res=%s", ..., self._can_min(), self._can_res())`
里的 `min=/res=` 是**守卫函数返回值**，不是命令类型！
- `cmd=0xf020 ... min=True res=False` = SC_MINIMIZE 且 `can_conceal()` 为 True → 吞掉并播放折叠
- `cmd=0xf120 ... min=False res=True` = SC_RESTORE 且 `can_reveal()` 为 True → 吞掉并播放展开
- `cmd=0xf120 ... min=True res=False` = **SC_RESTORE 打在非最小化窗口上**，`can_reveal()` False
  → 消息被吞、什么都不做（这是正确行为，不是 bug）

**终验通过的完整序列（FX 日志逐条对上）**
```
syscmd wparam=0xf020 → sprite conceal show=3ms → before(conceal)=38ms
  → run conceal dur=230ms → finish progress=1.00   （窗口 IsIconic=1）
syscmd wparam=0xf120 → sprite reveal show=2ms  → run reveal dur=280ms
  → finish progress=1.00                            （几何精确还原）
黄点 → sprite morph show=3ms → run morph dur=240ms → finish progress=1.00（满屏）
黄点 → sprite morph show=3ms → before(morph)=347ms → run morph dur=240ms
  → finish progress=1.00                            （unmaximize 后回到 38,130,1825,759）
```
- 去重生效：每条 `WM_SYSCOMMAND` 只有一条 `syscmd` 记录（Qt 双通道重复投递被吃掉）
- `_restore_max` 生效：最大化态最小化后再还原，正确回到满屏（而非普通尺寸）

**应用不会自己退出**：纯观察 150 秒面板一直在；后台启动的实例 40s~5min 后"干净退出"
（无 traceback、无 faulthandler dump、无 crashes/ 新文件）—— 是用户关窗或沙箱回收进程树，
**不是崩溃**。测试脚本用 `subprocess.Popen` 拉起的实例会被父脚本退出一起带走，
所以长时序测试必须用 `run_in_background` 起应用、另开命令跑测试。

**最大化态圆点定位的可靠规则**（`_apply_reserve()` 会把 margin 清零，圆点从
窗口顶往下 27px 变成 27px 但 x 也从 52 变 13）：
屏幕上**存在大面积黄色区域**（IDE 界面），"取最大黄色簇"会选错 →
必须**以红点的 y 为基准**（|Δy|<6）筛选同排黄簇，再用"x 在红绿之间"校验。

  `replace_lines {start_line, end_line, content}`（含边界）；`insert_after` 支持 `line`；
