## computer-control 插件：任务栏点图标 + 「↑」后台面板（`taskbar_open`）

用户诉求：「agent 应该直接先截图，如果发现程序图标在任务栏底部，就可以直接点击；
也可以尝试在任务栏后台面板里打开程序」。即把「打开/切换应用」的第 0 步从
`open_app` 改成「先看任务栏 → 点图标 → 翻「↑」面板 → 才 open_app」。

### 真机测量（本机 1920×1080 @125%，任务栏 y 1033~1079，高 47px）

- **任务栏背景是双向渐变**：横向因为壁纸/亚克力透出来，左区 (80,38,22)、右区
  (43,35,31)，差 40+ 级；竖向由深到浅。旧模型「区域一个背景色 + 色差阈值」
  在这里把左半条整片判成前景（实测 **100% 像素「像前景」**，图标一个都切不出）。
- **相邻图标之间只有 6~8px 缝**，而 Win11 图标 20~30px 宽。所以
  「连通域 + 12px 间隙合并」必然把相邻两个按钮并成一个（落点落在缝上 = 点了没反应）。
- 「↑」只有 **12×7**，被旧的最小高度 8 过滤掉了（面板流程因此找不到入口）。
- 「已启动指示条」在条带**最底 2~3 行**，宽 16~20px。

### 实现

1. `_band_base_cols`：逐列背景 `base(x)` 取条带**顶部 2 行**中位数（图标垂直居中，
   顶行必是纯背景），再做 5 宽中值滤波（顶行被污染时用邻居盖回来）。
2. `_band_vdelta` + `_band_fg`：可分离模型 `bg(x,y) = base(x) + vdelta(y)`。
   前景占比从 100% → **3%**。
3. `_band_runs`：**列活动度分段** —— 连续 `TASKBAR_SPLIT_GAP=3` 列零活动才切开
   （图标间缝 6~10px vs 字形内缝 1~2px，这是实测出来的分界线）。
4. `_band_slots`：每段取 y 范围，中心 y 用**中位 y**（外框会把底部指示条算进去，
   中心因此低 3~5px）；`running` 只在最底 4 行找、且必须明显窄于图标本体。
5. `TASKBAR_SLOT_MIN_H` 8 → **6**（「↑」7px 高）。
6. 面板流程的面板高度改按**虚拟桌面顶部**算（原来按 200px 抓取条带算，只截到
   面板最下面一条，变化量判定直接失败）。

真机验证：任务栏 12 个槽位全部框准（Start/微信/纸飞机/文件夹/终端/…/↑/英/拼/网络/音量/时钟），
12/12 注入落点落在方框内；「↑」面板展开后 5 个隐藏图标全部框准。

## 顶栏网络检测「离谱 bug」：UI 线程同步连公共 DNS + 误报离线

用户现象：企业网关封掉 Cloudflare/公共 DNS 的 53 端口后，模型 API 明明能用，
但程序每步操作甚至拖动窗口都卡，网络状态显示掉线、更新检查「获取失败」。

### 根因（`ui/agent_panel.py::_check_network`）

1. **在 UI 线程里做同步网络 I/O**：`socket.create_connection(("8.8.8.8",53), timeout=2)`
   失败再试 `223.5.5.5:53`。网关丢包（不回 RST）时每次检测等满 2s×2=4s，
   而轮询周期是 5s —— Qt 事件循环 80% 时间被掐住，这就是「拖窗口都卡」。
2. **判据本身错**：公共 DNS 的 53 被拦 ≠ 断网。拿它当在线判据必然误报「离线」。

### 修法

- 新增 `core/net_status.py`（纯逻辑、不依赖 Qt）：
  - 探测目标改为**应用真正依赖的端点**：系统代理 → 模型 API → 更新服务器；
    **彻底移除公共 DNS**（8.8.8.8/223.5.5.5/1.1.1.1）。
  - 三态判定：`traffic_ok`（应用请求刚成功）> 端点可达 > 系统可达性(NLM)；
    探测被拦但系统有链路 → **limited（黄）**，只有系统明确无链路才 offline（红）。
  - `probe()` 有**硬预算**（0.8s/目标、2.4s 总预算 + 外层 join 兜底）：
    `getaddrinfo` 不受 socket 超时约束，企业 DNS 卡住时单目标能拖几秒（实测 3.8s），
    故再套一层 daemon 线程到点即返回。
- `agent_panel`：`_check_network` 只起后台线程，结果经 `net_changed` 信号回主线程；
  连续失败退避 5→10→20→30s；接 `QNetworkInformation`（networklistmanager）做事件驱动复核。
- `agent_http` / `update_check`：请求成功即 `net_status.note_success()`（最强在线证据）。
- `update_check`：失败退避 30s→5min；错误文案区分超时/DNS/HTTP，不再笼统「网络异常」；
  手动检查失败时若应用在线，提示「仅更新服务器不可达，不影响使用」。
- `scripts/generate_spec.py`：hiddenimports 增加 `PyQt6.QtNetwork`（ui/*.py 会被 Cython 成 .pyd，
  PyInstaller 分析不到函数内导入）。
- 新增 `tests/test_net_status.py`（17 例）+ `scripts/_verify_net_fix.py` 真机验证脚本。

## 后台任务面板：最多 5 个 + 滚动 + 大命令实时出流

需求：最大显示 5 个后台任务，超出新任务置顶、旧任务下移，加滚动条可滑动查看；
且大型命令必须实时监听输出，让用户看到最新任务进度。

**核心层（为什么改）**：原先 `_exec_command_background` 只在命令**跑完后**才
`task.append_output(全文)`——长命令中途面板一片空白，看不出进度。而 `_run_command`
的 `status_cb` 只透传"运行时部署"进度，命令 stdout/stderr 完全不外流。
- `agent_tools._drain_pipe` 增加 `on_line` 回调；`_run_command` 增加
  `on_output` / `cancel_event` 参数（默认 None，旧调用方行为不变）。
- `agent_engine._exec_command_background`：`wait` 提到 6 小时 + 传 `on_output`
  实时增量，**已流出就不再追加全文**（否则整段重复）；`cancel_event` 让"取消"
  真正杀掉进程树，而不是只改 UI 状态。
- `agent_background`：`append_output` 加 100 万字符上限（丢头保尾，防长日志吃内存），
  暴露 `cancel_event` 属性。

**UI 层**：`_BackgroundTaskWidget` 改分块缓冲 `_buf`（超 20 万丢头保尾）+ 渲染
自适应节流（100/300/600ms）+ 超 12 万字符降级纯文本 + 贴底滚动（上翻不拽回）+
折叠态"最新一行"摘要（摘要按宽度省略，全文进 tooltip）；`_BackgroundTaskPanel`
用 QScrollArea，`_MAX_VISIBLE_TASKS=5`，新任务 insertWidget(0) 置顶，高度=前 5 张
之和，>5 出现滚动条；统一定时器每秒刷运行中耗时（原来每个流式 chunk 都带
duration=0，秒表被反复清零）。

**踩坑（重要）**：只设 `setWidgetResizable(True)` 时，QScrollArea 会把容器压到
minimumSizeHint → 卡片被挤扁、"内容>视口"永不成立，**滚动条死活不出现**。
修法：把内容真实总高写进 `tasks_container.setMinimumHeight()`。

**另一个坑**：offscreen(QT_QPA_PLATFORM) 下 `app.exec()` 会让顶层窗口被判为
不可见、布局随之失效，测试只能用 `processEvents()` 驱动（已有 UI 用例同样如此）。

**回归**：`tests/test_bg_task_panel.py`（8 例，全绿）；`test_tool_output_mount` /
`test_ask_dedup_empty` / `test_generation_progress_uiux` 47 项全绿。
注意 pytest 偶尔会从 `C:/Users/zhuzhu/Desktop/my first android app\tests\` 收走
无关用例，失败用例先看路径是不是本项目。

**文件**：core/agent_background.py、core/agent_tools.py、core/agent_engine.py、
ui/agent_panel.py、tests/test_bg_task_panel.py
