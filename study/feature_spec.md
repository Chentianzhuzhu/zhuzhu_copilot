# 在线记账本 MVP - 功能规划

## 一、MVP 定位

### 1.1 核心定位
- **产品定位**：轻量级个人记账工具，专注于快速记录日常收支
- **目标用户**：18-35岁，有记账意识但难以坚持的个人用户
- **核心价值**：极简记账体验 + 直观数据反馈

### 1.2 MVP 原则
- **砍掉非必要功能**：不做社交、不做投资、不做多币种、不做记账挑战
- **聚焦核心场景**：记账 → 查账 → 看统计 三件套
- **技术简单可控**：单用户架构，避免复杂权限设计

## 三、技术选型建议

### 3.1 前端技术栈

| 层级 | 推荐方案 | 备选方案 | 说明 |
|------|----------|----------|------|
| **框架** | Vue 3 | React | Vue 学习曲线平缓，适合快速开发 |
| **状态管理** | Pinia | Vuex | Pinia 是 Vue 官方推荐 |
| **UI组件库** | Vant 4 | Element Plus | Vant 专为移动端设计 |
| **图表库** | ECharts | Chart.js | ECharts 图表丰富度高 |
| **构建工具** | Vite | Webpack | Vite 启动快、开发体验好 |
| **样式方案** | TailwindCSS | SCSS | Tailwind 提升开发效率 |
| **HTTP客户端** | Axios | Fetch | Axios 功能更完善 |

### 3.2 后端技术栈

| 层级 | 推荐方案 | 备选方案 | 说明 |
|------|----------|----------|------|
| **语言** | Node.js | Python | Node.js 前后端技术栈统一 |
| **框架** | Express / Koa | Nest.js | 轻量快速，适合MVP |
| **数据库** | SQLite | PostgreSQL | SQLite 零配置，适合单机部署 |
| **ORM** | Sequelize | Prisma | Sequelize 功能完整 |
| **认证** | JWT | Session | JWT 无状态，扩展性好 |
| **API文档** | Swagger | Postman | Swagger 可自动生成文档 |

### 3.3 数据库选型对比

| 特性 | SQLite | PostgreSQL |
|------|--------|------------|
| 部署难度 | ⭐ 零配置 | ⭐⭐ 需安装服务 |
| 并发支持 | ⭐⭐ 有限 | ⭐⭐⭐ 优秀 |
| 查询性能 | ⭐⭐ 一般 | ⭐⭐⭐ 优秀 |
| 数据迁移 | ⭐⭐ 文件复制 | ⭐⭐ 需迁移工具 |
| 适合场景 | 单机应用 | 多用户并发 |

> **MVP建议**：优先使用 SQLite，部署简单，后续可平滑迁移至 PostgreSQL

## 六、风险提示

### 6.1 技术风险
| 风险点 | 影响 | 应对措施 |
|--------|------|----------|
| SQLite并发瓶颈 | 多用户时性能下降 | MVP阶段控制用户量，预留PG迁移方案 |
| 前端包体积过大 | 首屏加载慢 | 按需引入组件库，代码分割 |
| 移动端适配问题 | 不同屏幕显示异常 | 使用响应式方案，真机测试覆盖主流机型 |

### 6.2 产品风险
| 风险点 | 影响 | 应对措施 |
|--------|------|----------|
| 功能过于简陋 | 用户体验差 | 聚焦核心体验打磨，简化而非粗糙 |
| 缺乏吸引力 | 用户留存低 | 通过视觉设计和交互细节提升体验 |
| 功能缺失 | 用户吐槽 | 提前规划P1/P2功能，快速迭代 |
