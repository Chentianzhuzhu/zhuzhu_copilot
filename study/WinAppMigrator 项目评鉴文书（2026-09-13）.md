## 一、总览

**项目**：WinAppMigrator（zhuzhu Copilot）——Windows 桌面 AI Agent 应用，兼应用迁移、卸载、安全防护之能；集成 LLM 对话、浏览器自动化、TTS、屏幕操作、沙箱执行、技能/插件/工作流体系与自更新链路。

**体系三层**：

| 层 | 构成 | 实测规模 |
| --- | --- | --- |
| 桌面客户端 | `src/winapp_migrator/`（core 78 项、ui、skills、plugins、office 等） | Python 84 件、54,524 行；Cython `.c` 43 件、1,051,898 行 |
| 更新服务端 | `update-server/`（Spring Boot 3.2.5 / Java 21 / MySQL / Redis，兼官网与管理后台） | Java 19 件、1,177 行 |
| 交付链 | Cython 编译 → 代码签名 → PyInstaller → Inno Setup → 官网 | scripts 132 件 `.py`、8,371 行；installer 38 件 |

**其他实测**：tests 22 件、159 用例（本地全过，24.94 秒）；技能目录 25（有内容 23、空目 2）；全树 SKILL.md 25 件（主技能 23 + 插件 1 + 工作流预设 1）；插件 1、MCP 服务器 1、工作流模板 12 项；docs 7 件（含专项代码审查与设计文书）。

**版本库**：远端 `github.com/zhutianliangtom/securityappforwindows`；仅 `main` 一分支、**无版本 tag**；史稠（约三十六日、reflog 数百条）；末次提交恰涉「三省六部全编队」机制之修；**仓体现处残态**，且**推送停滞**（详见风险节）。

## 三、所优

**其一，架构与体量可观。** 客户端、服务端、交付链三层分明；core 内 `agent_*` 模块化整齐（引擎、工具、子 Agent、工作流、沙箱各司其职）；核心以 Cython 编译保护，兼取性能与防逆向。

**其二，安全体系真实且克制。** `config/security.json` 七目（YARA、勒索、弹窗、启动项、DNS、下载守卫、LLM 审计）皆有实现与调度；金丝雀文件、卷影复制（VSS）、规则全外置；YARA 缺失时优雅降级；签名可信厂商有快速通道；LLM 调用设预算与缓存，克制而不铺张。

**其三，工程质量与测试显著进步。** 22 测试文件、159 用例本地全绿（24.94 秒）；CI 已立（compileall + ruff、pytest、update-server 编译三岗）；docs/ 存专项代码审查（2026-08-29）与设计文书四篇（superpowers/specs），体例与深度俱佳。

**其四，交付链完整、证书纪律良好。** 编译→签名→打包→安装→更新→官网端到端贯通；签名私钥 `.pfx` 确未入库（已验：`git ls-files build/certs` 仅 `.bat`/`.cer` 二件）。

**其五，制度与势头。** 提交规范（`type(scope): 描述`）、临时脚本 `_` 前缀之约、工作日志连月不辍；旧评「无 CI/CD」之讥已自补——项目仍在快速演进（三十六日而成三层大观）。

## 四、所劣

**其一，文书滞后失实（对客之险）。** `README.md` 称「27 个内置技能」而实测主技能 23 有内容；称 `app/` 为「Kotlin 语音笔记子项目」而与实不符；`project_overview.md` 仍载「25 技能、15 测试、138 脚本」之旧数。同仓数字互牾，读者无所适从。

**其二，`app/` 名存实亡。** 实测仅存构建产物 17 件（15 `.xml` + 2 `.java`，全在 `app/build/` 下；无 `.kt`、无 `build.gradle`、无清单），源码无存，且与「构建产物不入库」之自约相悖。去留宜早决。

**其三，工程卫生欠修。** 根目录杂物可见（`-w`、`stdout.txt`、`_fix_button.py`、`mydir/`、`hello_world.py` 等）；`skills/` 两目凌空（`screen_operate`、`ui-automation`）；tests 三件未入籍（`test_dock_layout`、`test_llm_header_guard`、`test_session_naming`——CI 永不收之）；`.gitignore` 两处失修（`scripts/_` 缺通配、`scripts._*` 疑误写），致 40 枚 `_` 脚本在库。

**其四，覆盖率未量化。** 用例虽全过，但 UI、迁移引擎、TTS 等大面未测；CI 中 ruff 以 `|| true` 放行、无覆盖率门控。

**其五，杂项。** 无版本 tag、未见 LICENSE/CHANGELOG；技能数三说并载（23/25/27）；提交者邮箱含手机号（公开仓下有隐私之虞）；引擎生成之 `.c`（105 万行）入库与 `.gitignore` 新规相悖（历史遗留）。

## 五、险虞

### 高

**1. 明文密钥入库，且外推证据充分（最急）。** `src/winapp_migrator/core/agent_llm.py` L29 载默认服务商密钥（明文；本稿脱敏，不录全值）。该文件受版控（`git ls-files` 已验）；`.git/logs/refs/remotes/origin/main` 载五次「update by push」，**末次止于 8 月 15 日**，而密钥提交先于诸推——**已入 GitHub 远端**（仓之可见性本地不可判，须自查）。又：8 月 15 日后推送停滞，九月之提交多滞留本地。处置：立即作废轮换；改环境变量或本地加密配置（项目已有模型配置本地加密之基建）；如须清史，用 BFG/filter-repo 后强推，并全量轮换。

**2. 版本库对象缺损（工程急症）。** `git log`、`git status` 皆败（父提交 `1b32d667…` 与 HEAD 树不可读）；`git fsck` 报 `origin/HEAD`、`origin/main` 指向失效对象（`1e7439d8…`）、reflog 多条失效、`tmp_pack_Jr3zXr` 为残留垃圾。处置：先全量备份（含 `.git`）→ 清残件 → `fetch` 核对远端 → `fsck --full`/`gc` → 不可复则重克隆归魂。

### 中

**3. 更新链信任。** `UpdateController.java` L77-81 以 `X-Forwarded-Proto` + `Host` 拼重定向地址；`update-server/deploy/nginx.conf` 下载段未转发此二者（仅 `X-Real-IP`），与主页段（转发 `Host`/`X-Forwarded-Proto`）不一，配置与代码期待相左；且 80→443 跳转以 `$host` 回显。头可控时，更新地址可被导向敌域（投毒/钓鱼）。宜固定基准 URL 白名单，勿信请求头。

**4. UI/UX 包代码执行。** `agent_ui_ux.py` L2304 以 `exec` 执行 AI 生成之 `build_ui.py`（有命名空间与标识符白名单式校验；另 L3098 有 compile 语法预检），但非真沙箱。建议子进程隔离与更严校验。

**5. 签名信任过宽。** `deep_analyze.py` L85 起：仅取证书显示名（CN）子串命中可信名单即判 `clean`，未施 WinVerifyTrust 全链校验（过期、吊销、归属不察）。建议整链验签后放行。

**6. 证书与隐私管理。** `.pfx` 未入库（已验），然本地私钥保管与构建环境隔离宜升级（硬件密钥/隔离构建）；提交者邮箱含手机号，宜改 noreply。

### 低

**7. 可观测性与调优。** 安全模块缺可视化事件日志与用户侧反馈入口；误报率未调；`security.json` 之 `llm.api_key` 实为空串（旧稿「明文凭据」之说与实不符，勘正）。
