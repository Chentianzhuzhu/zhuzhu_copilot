# 在线记账本 MVP - 产品方案汇总

> 文档版本：v1.0
> 更新日期：2026-01-15
> 项目负责人：产品经理

---

## 一、项目概述

### 1.1 产品定位
- **产品名称**：在线记账本
- **产品定位**：轻量级个人记账工具
- **目标用户**：18-35岁有记账意识的个人用户
- **核心价值**：极简记账体验 + 直观数据反馈

### 1.2 MVP 原则
- 砍掉非必要功能：不做社交、不做投资、不做多币种
- 聚焦核心场景：记账 → 查账 → 看统计
- 技术简单可控：单用户架构，避免复杂权限设计

## 二、模块划分

### 2.1 核心模块（P0）
| 模块 | 功能描述 |
|------|----------|
| **记账功能** | 快速录入金额、选择收支类型、分类、备注、日期 |
| **账单管理** | 列表展示、日期分组、筛选、分页 |
| **分类管理** | 预设分类、自定义增删改 |
| **账本管理** | 多账本支持、默认账本设置 |
| **统计概览** | 月度汇总、支出占比饼图、趋势折线图 |

### 2.2 增强模块（P1）
| 模块 | 功能描述 |
|------|----------|
| **筛选功能** | 类型/分类/日期范围/关键词搜索 |
| **交互优化** | 滑动删除、长按菜单、批量操作 |
| **用户系统** | 登录注册、头像上传 |

### 2.3 延期模块（P2）
- 数据导出（Excel/PDF）
- 预算管理
- 多端同步
- 主题切换
- 每日提醒

## 三、接口要点

### 3.1 核心 API 列表
| 模块 | 方法 | URL | 说明 |
|------|------|-----|------|
| 账目 | POST | /api/v1/transactions | 创建账目 |
| 账目 | GET | /api/v1/transactions | 查询列表（支持分页、筛选） |
| 账目 | PUT | /api/v1/transactions/{id} | 更新账目 |
| 账目 | DELETE | /api/v1/transactions/{id} | 删除账目 |
| 分类 | GET | /api/v1/categories | 获取分类列表 |
| 分类 | POST | /api/v1/categories | 创建分类 |
| 分类 | PUT | /api/v1/categories/{id} | 更新分类 |
| 分类 | DELETE | /api/v1/categories/{id} | 删除分类 |
| 账本 | GET | /api/v1/account_books | 获取账本列表 |
| 账本 | POST | /api/v1/account_books | 创建账本 |
| 账本 | PUT | /api/v1/account_books/{id}/default | 设置默认账本 |
| 统计 | GET | /api/v1/statistics/monthly | 月度统计 |
| 统计 | GET | /api/v1/statistics/trend | 趋势统计 |

### 3.2 数据模型关键设计
- **账目表**：关联账本、分类，存储金额、类型、备注、日期
- **分类表**：支持自定义，区分收入/支出类型
- **账本表**：支持多账本，有默认标识

## 五、风险与应对

### 5.1 技术风险
| 风险点 | 影响 | 应对措施 |
|--------|------|----------|
| SQLite并发瓶颈 | 多用户时性能下降 | MVP阶段控制用户量，预留PG迁移方案 |
| 前端包体积大 | 首屏加载慢 | 按需引入组件库，代码分割 |
| 移动端适配 | 不同屏幕显示异常 | 响应式方案 + 真机测试 |

### 5.2 产品风险
| 风险点 | 影响 | 应对措施 |
|--------|------|----------|
| 功能简陋 | 用户体验差 | 聚焦核心体验打磨细节 |
| 缺乏吸引力 | 用户留存低 | 通过视觉和交互细节提升体验 |
| 功能缺失 | 用户吐槽 | 规划P1/P2功能快速迭代 |
