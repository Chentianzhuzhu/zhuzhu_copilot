# code-map：先看清仓库，再动手

## 什么时候用

- 用户问「这个项目多大」「代码主要在哪」「哪些文件最重」「先帮我摸清结构」；
- 你要在一棵陌生目录里做重构 / 批量修改，先建立规模认知再决定策略；
- 判断某目录是否值得全量读取（行数太大就别整文件读，改用 grep / search_code 定位）。

## 怎么调

```
code_map(path="C:/path/to/repo")          # 必填建议显式给 path
code_map(path="...", depth=3, top=12)     # depth 1~6（默认 4），top 3~30（默认 8）
code_map()                                # 不带参数 = 上次扫描过的目录（或当前工作目录）
```

## 读结果

- **代码行数**只统计代码/文本类后缀（`.py/.ts/.js/.md/.json/...`），二进制与媒体跳过；
- **按目录**是相对根目录的第一段，用来看「重心在哪个子模块」；
- **最大的文件**按行数排序——这些是读文件的成本大头，优先用 `grep` / `search_code` 定位片段；
- 结果标注「已达上限截断」时说明目录过大（>2 万文件或 >20s），此时用 `depth=2` 或指定子目录再扫；
- 默认排除 `.git` / `node_modules` / `dist` / `build` / `__pycache__` 等依赖与产物目录，符号链接不跟随。

## 边界

- 只读扫描，不改任何文件；
- 不要用它替代精确检索：要找具体实现仍用 `grep` / `search_code`；
- 用户没给路径且上次没记录时，先用 `ask_user` 问清目录，不要瞎猜一个盘符根目录去扫。
