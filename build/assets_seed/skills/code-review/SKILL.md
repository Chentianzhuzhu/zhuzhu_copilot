# Code Review 技能

## 触发条件
当用户要求代码审查、检查代码质量、review代码时调用。

## 执行流程

### 第一步：定位待审查文件
1. 使用 list_directory 了解项目结构
2. 使用 read_file 读取待审查的源代码文件
3. 若未指定文件，询问用户需要审查哪个文件

### 第二步：逐层审查
按以下顺序检查每个文件：

#### 2.1 逻辑正确性
- 算法实现是否正确
- 边界条件处理是否完备
- 异常分支是否覆盖
- 数据流是否合理

#### 2.2 安全与权限
- 是否存在注入风险（SQL、命令、XSS）
- 路径操作是否验证用户输入
- 敏感信息是否硬编码
- 权限检查是否到位

#### 2.3 错误处理
- 异常是否被妥善捕获
- 错误信息是否友好
- 资源是否正确释放（文件、连接、锁）
- 是否有必要的日志记录

#### 2.4 可维护性
- 函数/类命名是否清晰
- 代码复杂度是否合理
- 是否有重复代码
- 注释是否必要且准确
- 是否符合项目编码规范

### 第三步：输出审查报告
格式：
```
## 代码审查报告

**审查文件：** <文件名>
**审查时间：** <时间>

### 🔴 严重问题
- 文件: 行号 - 问题描述
  建议：修复方案

### 🟡 一般问题
- 文件: 行号 - 问题描述
  建议：改进方案

### 💡 优化建议
- 描述性建议

### ✅ 优点
- 值得保留的好实践
```

### 第四步：等待反馈
- 询问用户是否需要修复建议
- 或继续审查下一个文件

## 注意事项
- 每步完成后确认用户意图
- 严格聚焦代码本身，不扩展讨论范围
- 问题按严重程度分级，避免信息过载
