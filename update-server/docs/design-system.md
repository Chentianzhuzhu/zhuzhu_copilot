# 官网视觉系统：装配说明书（ASSEMBLY MANUAL）

> 适用对象：`update-server` 对外官网（首页 / 界面实拍 / 下载 / 常见问题 / 用户反馈 / 关于 / 站点地图）
> 唯一配色与令牌来源：`src/main/resources/static/css/site.css` 的 `:root`

---

## 一、现状分析

改造前项目里存在三套互不相干的前端表面：

| 表面 | 位置 | 面向谁 | 问题 |
| --- | --- | --- | --- |
| 产品官网 | `update-server`（Thymeleaf） | 下载产品的普通用户 | 视觉语言与产品定位脱节 |
| 账号中心 | `auth-server/static/login` | 注册 / 登录用户 | 配色为紫底 + 玫红强调（`#1a1a2e` / `#e94560`），与官网完全不同源 |
| 旧市场端 | `market-server` | 遗留页面 | 已不在主链路上 |

官网自身可核对的具体问题（均已在本轮修正）：

1. **品牌名与产品名不一致**：`ContentService.defaults()` 里 title 仍是 `WinAppMigrator`，而产品已经是 zhuzhu Copilot。
2. **首屏右栏是功能目录的第二遍**：没有截图时渲染一块「产品概览」索引，把下一节的功能列表又列了一次，信息重复且没有新增事实。
3. **能力用卡片阵列表达**：三张等宽卡片 + 图标 + 标题 + 一行说明，是 AI 生成落地页最典型的骨架。
4. **双主色**：电光蓝 `#3D7DFF` 搭配青绿 `#7DF9E4`。青绿是「AI 产品」最容易辨认的配色指纹之一。
5. **展示层级均质**：8 个区块视觉权重几乎相同，读者无法快速区分「它能干什么 / 凭什么信它 / 怎么拿到手」。
6. **动效以漂浮为主**：视差 + 倾斜 + 计数，服务于"炫"，不服务于"看懂"。

## 二、目标用户与任务

官网只有一个核心转换动作：**把安装包下载下来并装上**。按阻力排序，用户分三层：

| 用户 | 场景 | 真实顾虑 | 官网必须先回答 |
| --- | --- | --- | --- |
| 主力：非技术 Windows 用户 | C 盘红了、老机器卡、听说 AI 能替他操作 | 「点错会不会把系统搞坏」「我的软件设置会不会丢」 | 会改动什么、不会改动什么、能不能反悔 |
| 次级：效率型知识工作者 | 重复性的桌面操作想交给 AI | 「它到底能替我做什么」「要不要联网」 | 能力边界 + 本地/云端的界线 |
| 长尾：开发者 | 想接自己的模型 / 写插件 | 「可扩展性如何」 | README 与 GitHub，不是首页的诉求 |

关键结论：**首页不需要更"酷"，需要更"可信"**。恐慌点不是性能数字，而是不可逆的操作。

## 三、核心功能与产品特色

- 应用迁移：整目录搬迁 + 注册表、快捷方式、AppData 同步重写，目标是不重装、不丢配置。
- AI 助手：观察屏幕 → 调工具 → 截图验证的闭环，真实操作本机。
- 系统优化：内存、启动项、安全防护。
- 工程特色：命令沙箱 + 路径白名单、破坏性操作二次确认、本地执行（仅推理走云端）。

---

## 四、设计方向：把官网做成一份装配说明书

**为什么不是"更酷的落地页"**：炫技型页面的说服逻辑是"我们很强"，而目标用户要的是"我不会搞坏"。说明书的说服逻辑是编号、规格、可核对的条目——它把"专业"翻译成"可验证"。

四条落地原则：

1. **只有一个彩色（深蓝）**，只出现在"可以操作"的地方：按钮、当前章节、焦点环、图纸标注线。大面积铺色会稀释它的指示性。
2. **不用圆角与投影分层**，用 1px 描边、表面色差与留白。工业界面的深度来自结构。
3. **元信息走等宽字体**（编号 / 版本 / 体积 / 日期）：它们是用来核对的，不是用来阅读的，等宽才能纵向对齐。
4. **动效只解释状态变化**，不做装饰性漂浮。

## 五、视觉系统

### 5.1 色板（四色体系，全部可查）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg-color` | `#0A0B0D` | 纸面（近黑，非纯黑：纯黑在 OLED 上边界会糊） |
| `--surface-1/2/3/4` | `#0F1114` / `#14171B` / `#1B1F24` / `#232830` | 四档表面，越亮越靠前 |
| `--text-color` | `#F5F5F5` | 标题与正文主体（对比度 ≈ 19:1） |
| `--text-muted` | `#A9AFB8` | 说明文字（≈ 8:1） |
| `--ink-faint` | `#8A9099` | 标注 / 编号（≈ 6:1，仍高于 AA 的 4.5:1） |
| `--theme-color` | `#1E40AF` | 深蓝：主按钮、CTA 底、当前章节 |
| `--blue-hover` | `#2A55D0` | 悬停 |
| `--accent-color` | `#7D96E8` | 暗底上的蓝色文字、标注线、焦点环 |
| `--line` / `--line-strong` | `rgba(200,210,230,.13)` / `.28` | 两级描边，唯一的层级工具 |

**没有红/绿/黄语义色**。状态靠文字、图标与位置表达：成功是深蓝实底 + 白色对勾，失败是深蓝描边条 + 警示图标。这样单色屏幕与色觉障碍下依然可读，也避免整页被状态色拉走注意力。

### 5.2 字体

| 角色 | 字体栈 | 理由 |
| --- | --- | --- |
| 正文 / 标题 | `Segoe UI Variable Text → Segoe UI → Microsoft YaHei UI → PingFang SC → system-ui` | 全部系统栈，零网络请求。目标用户里有大量老机器，首屏不该等字体 |
| 元信息 / 数字 | `Cascadia Mono → Cascadia Code → Consolas → ui-monospace` | 编号、版本、体积需要纵向对齐，等宽是语义而不是风格 |

字阶（`--text-xs` … `--text-hero`）：`.75 / .875 / 1.0625 / 1.375 / clamp(1.85–2.6) / clamp(2.5–4.35)` rem。
正文 **17px / 行高 1.85**：中文正文比西文需要更大字号与行距，主要读者包含中年用户。
标题 `letter-spacing: -.018em`：中文不能像西文那样收到 -0.04em，会粘连；这里只做极轻收紧 + `text-wrap: balance` 控制断行。

### 5.3 栅格与空间

- 内容最大宽 1240px，视口两侧留 32px。
- 章节头为 **1.1fr / 0.9fr 非对称两栏**（标签+标题在左，副标在右），替代"居中堆叠"。
- 区块内边距 `clamp(64px, 8vw, 112px)`，间距基数为 8px，但用 4/8/16/24/40/64/104 的大跨度跳跃避免"处处等距"的表格感。
- 首屏 `1.06fr / 0.94fr`，左侧文案、右侧图幅。

### 5.4 图标

全部为 24 网格、1.6–1.8 描边的线性图标，无底色圆形、无填充色块；图标容器是一个 1px 描边方框（`38×38`），悬停时描边与图标同时转为深蓝。品牌标记是"三格盘位"图形（上格填充深蓝），比十字网格更贴"磁盘/面板"的产品语义。

## 六、页面结构

1. **章节索引（spine）**：≥1400px 时左侧常驻 `01–06`，与滚动联动；章节名放在 `aria-label`，悬停展开。它是长页面的定位器，也是"说明书"这一隐喻最直接的载体。窄屏隐藏，顶部导航已覆盖同样的跳转。
2. **首屏**：`zhuzhu copilot / WINDOWS AGENT` 小标 → 大标题（后台 slogan）→ 描述 → 主/次按钮 → 版本行。右栏在**没配截图**时渲染 `FIG. 01 迁移保留项` 图幅：源路径与目标路径并列，下面逐条列出会被同步重写的东西。配了截图就老老实实显示截图——不伪造产品界面，也不编造"剩余 4.2 GB"这类运行时数字。
3. **规格条**：直接渲染后台「系统要求」四项，形成一条可核对的 datasheet。
4. **能力清单**：`编号 / 图标 / 能力名 / 说明` 四列的行式表格，悬停整行右移 6px 并展开左侧 2px 蓝色标记。行式布局让三条能力可以自上而下扫读，卡片阵列做不到。
5. **数据一览**：先画一条 8px 刻度尺，再给超大等宽数字。数字是"测量结果"，不是装饰。
6. **产品优势**：2×2 图幅，四角有定位角标（1px L 形），悬停时角标变亮。没有圆角、没有阴影。
7. **常见问题**：原生 `<details>` 行式编号，加号旋转 45° 变叉，展开时只做透明度与 6px 位移，不做高度动画。
8. **更新日志**：一张"发布单"，等宽版本号 + 体积/下载量 + 破折号条目。
9. **结尾行动区**：整块深蓝 + 白色网格，读作"盖上去的一枚印章"；主按钮反白。

## 七、动效

| 场景 | 实现 | 时长 / 曲线 |
| --- | --- | --- |
| 区块入场 | `translate3d(0,14px,0)` + 透明度，按 `--d` 错峰 | 0.5s `cubic-bezier(.16,1,.3,1)` |
| 页面进入 | 仅 8px 位移，**不做透明度** | 0.72s 同曲线 |
| 能力行悬停 | 整行 `translateX(6px)` + 左侧蓝条 `scaleY(0→1)` | 0.3s |
| 数字 | 进入视口后一次性 rAF 递增，到顶即停 | 1.1s 三次缓出 |
| 导航 | 顶部 1px 滚动进度 + 下边框渐显 | 0.3s |
| 焦点 | `:focus-visible` 2px 深蓝外环 | 即时 |

性能红线（由 `tests/test_static_site.py` 长期看住）：只动 `transform / opacity`；禁止背景模糊、文字投影、常驻合成层提升、径向渐变；`prefers-reduced-motion` 下全部关闭。

页面进入刻意**不做透明度过渡**：一旦动画在某些环境不播放（打印、后台标签页被节流、省电模式），`opacity: 0` 起步 + `fill-mode` 会把整页永久留在透明状态。位移式入场即使不播放，终态也与静态样式完全一致。

## 八、设计决策 ↔ 需求 / 特色 对应表

| 设计决策 | 对应的用户顾虑 | 对应的产品特色 |
| --- | --- | --- |
| 唯一彩色、只用于可操作处 | 降低"这里能点吗"的判断成本 | 工具属性 > 营销属性 |
| 1px 描边替代圆角与阴影 | 界面不"软"，像仪表而不像玩具 | 系统级操作需要精确感 |
| 章节编号 + 左侧索引 | 长页面不迷路，可回看 | 能力有明确边界，可逐条核对 |
| 能力用行式清单而非卡片 | 一眼扫完三条能力，不用横向比对 | 三项能力是并列关系，不是三个卖点 |
| 首屏 `FIG.01 迁移保留项` | 直接回答"会不会丢配置" | 注册表 / 快捷方式 / AppData 同步重写 |
| 规格条复用后台「系统要求」 | 装之前就知道要什么权限、多少空间 | 管理员权限、约 300 MB |
| 数字用等宽 + 刻度尺 | 数字可信、可比较 | 下载量与版本是客观事实 |
| 无红绿语义色 | 色觉差异下仍能读懂状态 | 安全设计不依赖"看起来很安全" |
| FAQ 用原生 `details` | 无 JS 也能展开；键盘可达 | 迁移、联网、误删三大疑问前置 |
| CTA 整块深蓝 + 反白按钮 | 唯一焦点，不与其他蓝色按钮抢 | 结尾只保留一个动作 |
| 系统字体栈、零字体请求 | 老机器首屏不空白 | 本地执行、轻量开箱即用 |

## 九、工程约束与验证

- 配色唯一来源是 `site.css` 的 `:root`；`head.html` 不再注入第二份变量（否则后台改色会静默失效）。
- 所有文案仍由后台内容驱动：标题、标语、描述、能力、优势、FAQ、系统要求、页脚、关于，模板里不写死业务内容。
- 无 JS 与 `prefers-reduced-motion` 下内容必须完整可见；打印时强制回到终态（`@media print`）。
- 回归口径：
  - `python tests/test_static_site.py` → 72 项：色板白名单、禁止 emoji、字阶令牌、动效合成层约束、片段引用、DOM id 与脚本一致、SEO 资源。
  - `python tools/run_tests.py` → 64 项：真实 Thymeleaf 渲染、SEO 头部、区块标题只出现一次、页脚时间戳、错误页自包含。
  - `python tools/run_tests.py --preview && python tools/preview_server.py --port 8099` → 本地真实预览。
