# computer-control：电脑操控

本插件让 AI 直接操控 Windows（Win10/11）：**优先用 UI Automation 按控件名称/类型精确操作**，
识别不到元素时才退回「看截图猜坐标」。两种模式下本地 Web UI 都实时展示画面与操作日志，
用户可随时用真鼠标/键盘打断、或在 Web UI 上一键接管。

## 何时使用

- 用户要求「帮我操作电脑/点开某个软件/在界面上完成某件事」，且内置工具（文件、命令、浏览器）无法完成时。
- 目标只能通过图形界面完成（安装向导、桌面应用、系统设置、需要看界面判断的操作）。
- 能在命令行/文件工具里完成的，优先用那些工具（更快更稳），不要用界面操控绕路。

## 第一步：打开可视化界面（必须，且必须先做）

1. 调用 `web_url` 取得本地可视化地址；
2. 用 `browser_open` 打开给用户 —— 用户要能实时看到画面、操作日志，并随时接管；
3. 整个任务期间保持该页面打开；任务结束时告诉用户可以在页面上回看操作过程。

## 核心原则：元素优先，坐标兜底

**这是本插件最重要的使用纪律。** 按下面的顺序选工具，能省掉大量截图往返与点错：

| 场景 | 首选工具 | 不要用 |
| --- | --- | --- |
| 找按钮/输入框/列表/滑块 | `list_elements` | `screen_shot` 猜坐标 |
| 点某个具名控件 | `click_element(name=...)` | `click` 传坐标 |
| 往输入框写字 | `type_element(name=..., text=...)` | `click` + `type_text` |
| 滚某个容器 | `scroll_element(name=..., delta=...)` | `scroll` 传坐标 |
| 拖滑块/列表项/图标 | `drag_element(from_name=..., to_name=...)` | `drag` 传坐标 |
| 界面无障碍信息缺失（Canvas/游戏/远程桌面/自绘控件） | `screen_shot` + `click`/`drag` 坐标 | — |

原因：元素工具拿到的是控件**真实矩形中心**，不受缩放、主题、DPI、动态布局影响；
而看图猜坐标会随窗口大小、分辨率、动画状态全部漂移。

## 标准流程

1. `screen_info`：确认分辨率、元素识别是否可用、当前前台窗口、接管状态；
2. `list_windows` → 选定目标窗口（复杂桌面上先确认窗口，别对着错的窗口操作）；
3. `manage_window(action="activate")`：**点击前务必先激活目标窗口**，避免点进被遮挡的窗口；
4. `list_elements`：读出目标控件的名称/类型/中心坐标（带可点击/可输入/可滚动/可拖拽标记）；
5. 行动：`click_element` / `type_element` / `scroll_element` / `drag_element`；
6. **行动后必须重新 `screen_shot` 验证**（对话框是否弹出、内容是否输入正确），再进行下一步；
7. 元素识别不可用或目标不在元素树里（如游戏画面、远程桌面、Canvas 自绘）时，
   改用 `screen_shot` + `zoom_in` 精确定位 + 坐标类工具。

**坐标约定**：所有工具的 x/y 都使用**当前截图基准的图像像素**（黑底红线下方的刻度数字同基准），
插件自动换算为屏幕物理坐标 —— 不要把截图坐标再手动乘以缩放比例。

**元素工具的定位方式**：`name` 是控件名的子串匹配（忽略大小写）；`type` 是控件类型
（Button / Edit / List / ScrollBar / Slider / MenuItem / Checkbox / TabItem…）。
匹配到多个时会返回候选列表并要求你用 `index` 指定 —— **按候选列表里的序号选，不要瞎猜**。

## 面对复杂桌面的处理策略

真实桌面远比单窗口复杂，以下情形按此处理：

- **窗口抢焦点**：子窗口/对话框/安装向导常在启动时抢焦点。点击前先
  `manage_window(action="activate")`；工具返回「目标窗口未成为前台」时说明系统拒绝了置顶
  （锁屏/安全桌面/UAC），此时点击可能落空 —— 先处理前置窗口或请用户手动切窗口。
- **弹窗延迟出现**：不要固定 `sleep` 猜测，用 `manage_window(action="wait", title="…")`
  等窗口真正出现，比任何固定等待都可靠。
- **窗口位置乱飞**：用 `manage_window(action="maximize")` 最大化目标窗口再操作，
  元素更多也更稳定；需要精确坐标时用 `move` 摆好位置。
- **找不到目标窗口**：先 `manage_window(action="state")` 看全部窗口，确认标题再操作。
- **虚拟桌面隔离**：用户要求「别动我的窗口 / 后台静默」时，先
  `open_virtual_desktop(action="new")`，**任务结束必须** `open_virtual_desktop(action="back")` 返回。

## 输入方式

点击/长按/拖拽/滑动**优先走 Win10/11 真实触控注入**（触控 tap、触控长按、带惯性的触控滑动）；
本机若没有可用的触控数字化仪（如普通台式机），插件会**自动回退鼠标模拟**，`screen_info` 会如实
标明当前实际输入方式 —— 此时请用 `scroll` 滚动、用 `click(button="right")` 代替长按呼出菜单。

## 屏幕边缘彩色光环（用户提示）

AI 真正操控桌面（点击/输入/滚动/拖拽/拖窗口等）时，屏幕四边会亮起**彩色流光光环**，
提示「电脑正在被自动操作」。它鼠标穿透、不抢焦点、不挡视线，停止操控后淡出。

- 光环亮起 = AI 正在操作你的桌面，**此时不要抢鼠标**，否则会被判定为「用户接管」；
- 用户抱怨「屏幕边缘闪得慌」→ `aura(action="off")` 关闭；
- 纯查询类工具（`screen_shot`/`list_elements`/`list_windows`）**不会**点亮光环。

## 用户打断与接管（硬性协议）

工具结果里出现「用户已接管」或「已被用户暂停」时：

1. **立即停止一切操控**，不要再尝试点击/输入，也不要换坐标重试；
2. 向用户简要汇报：已执行到哪一步、当前界面状态、剩余步骤；
3. 若当时在独立虚拟桌面容器中，提示用户「可自行按 Win+Ctrl+← 返回原桌面，或点可视化界面上的
   「恢复」让我返回」；
4. **只有用户明确说「继续」后**，才可以调用 `control(action="resume")` 清除接管标记并继续；
   用户没说继续时，绝不允许自行调用 resume、也不得用其他工具绕过。
5. 自己判断该把控制权交还用户时（例如需要用户输入密码、做主观选择），主动调用 `control(action="take_over")`。

## 工具速查

**感知**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `screen_info` | 环境信息（屏幕/输入/元素识别/光环/前台窗口/状态） | 无 |
| `list_windows` | 可见窗口列表 | 无 |
| `list_elements` | **列出界面元素**（类型/名称/中心/能力标记） | `title`/`hwnd`、`name`、`type`、`only` |
| `screen_shot` | 截屏返回给 AI（网格+刻度+准星） | `mode=full\|window`、`title`/`hwnd` |
| `zoom_in` | 局部放大精确定位 | `x`、`y`、`size`、`factor` |

**元素级操作（优先用）**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `click_element` | 按名称/类型点击控件 | `name` 或 `type`、`index` |
| `type_element` | 定位输入框并输入文本 | `name`/`type`、`text` |
| `scroll_element` | 在指定容器内滚动 | `name`/`type`、`delta` |
| `drag_element` | 拖元素到元素/坐标 | `from_name`、`to_name` 或 `to_x/to_y` |

**坐标级操作（兜底）**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `click` | 点击（触控优先 tap） | `x`、`y`、`button`、`clicks` |
| `long_press` | 长按（触控长按出菜单） | `x`、`y`、`duration` |
| `drag` | 拖拽 | `x1`、`y1`、`x2`、`y2` |
| `swipe` | 滑动（触控惯性滚动） | `x1`、`y1`、`x2`、`y2` |
| `select` | 拖选文本/区域 | `x1`、`y1`、`x2`、`y2` |
| `scroll` | 滚轮滚动 | `delta`（正上负下）、`x`、`y` |
| `type_text` | 输入文本（支持中文） | `text` |
| `key_press` | 按键/组合键 | `key`（如 `enter`、`ctrl+c`） |
| `copy` / `paste` | 复制 / 粘贴 | `text`（粘贴时可先写入） |

**窗口与容器**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `manage_window` | 窗口管理：`state`/`activate`/`maximize`/`minimize`/`restore`/`move`/`close`/`wait` | `action`、`title`/`hwnd`、`x`/`y`/`w`/`h` |
| `open_virtual_desktop` | 虚拟桌面容器 | `action=new\|back\|next\|prev` |
| `control` | 状态查询/交还控制权/恢复 | `action=status\|take_over\|resume` |
| `aura` | 屏幕彩色光环开关 | `action=on\|off\|state` |
| `web_url` | 可视化界面地址 | 无 |

## 失败处理与降级

- `list_elements` 返回「未识别到匹配元素」→ 先放宽条件（去掉 `name`/`type`/`only`，
  或设 `include_offscreen=true`）；仍没有说明该界面无障碍信息缺失，改走截图 + 坐标。
- 报「元素识别不可用」→ UIA 在当前环境不可用（`screen_info` 会说明原因），
  **直接改用 `screen_shot` + 坐标类工具**，不要重试元素工具。
- 报「匹配到 N 个元素」→ 按返回的候选列表选 `index`，或把 `name` 取得更精确。
- 元素工具点空了 → 先看它返回的「注意：目标窗口未成为前台」提示，先 `activate` 再点。
- 连续两次操作失败（目标找不到/坐标无效/界面无变化）就停下来 `ask_user` 澄清，不要盲目重试。

## 安全红线

- 禁止用本插件执行不可逆操作：格式化/分区、删除系统文件、关机/重启/注销、修改系统关键设置、卸载软件，
  除非用户在本次对话中明确要求并已确认；
- 输入密码、支付、验证码等敏感信息前必须先 `ask_user` 让用户自己决定（可提醒用户在 Web UI 上接管自行输入）；
- 操作范围尽量限定在用户指定的目标应用/窗口内，不要顺手改动其他窗口的内容；
- 汇报要如实：没点到的不要声称点到了，拿不准就重新截屏确认。
