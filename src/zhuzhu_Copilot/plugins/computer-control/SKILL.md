# computer-control：电脑操控

本插件让 AI 直接操控 Windows（Win10/11）：**一切操作都基于坐标** ——
先 `screen_shot` 看清楚界面、读出目标的像素位置，再 `click` 点过去。
本地 Web UI 全程实时展示画面与操作日志，用户可随时用真鼠标/键盘打断、或在 Web UI 上一键接管。

> **本插件不读取界面的控件树。** 不存在「按控件名点击」这类工具，也不会有任何工具
> 返回「这个窗口里有哪些按钮」。定位目标只有一条路：**看图 → 取坐标 → 点击**。
> 这条纪律要贯穿整个任务，不要等工具报错才发现。
>
> **但「看图取的坐标」是估出来的**，所以点击默认会做**像素级元素吸附**：把坐标修正到
> 附近那个控件的**落点**——前景质量的质心，且必须落在元素自身上（纯像素连通域判定，
> 不依赖控件树，故自绘界面同样有效）。比外接框中心更准：不对称形状（气泡带尾巴、
> 播放键、箭头）不被伸出去的那块拽偏；环形/凹形元素不会点进洞眼里。
> 拿不准时先 `refine_point` 看图确认再点。

## 最短路径（先读这里）

**切应用 / 发消息这类高频任务，按这张表走，别绕路：**

| 想做的事 | 一步到位的做法 |
| --- | --- |
| 动手之前 | `screen_shot(mode="full")` 看一眼任务栏和当前前台，别猜坐标（**没有截图基准时 click 会被拒绝**） |
| 切到已在运行的应用 | `taskbar_open(name="微信")` 看状态 → 图标在就 `taskbar_open(index=N)` 直接点 |
| 图标不在任务栏可见区 | `taskbar_open(where="panel")` 展开右侧「↑」，再按编号点 |
| 应用没窗口但进程在跑（托盘） | `open_app(name="微信")` 会回任务栏原图+坐标表 → `open_app(name="微信", index=N, where="panel")` 一步点出来 |
| 应用根本没在运行 | `open_app(name="微信")` 自动启动；已知没跑想跳过检查就 `open_app(name="微信", launch=true)` |
| 点一个看得见的目标 | `refine_point(x,y)` 挑编号 → **`click(cand=编号)`**（坐标由插件按候选落点算，不用抄数字） |
| 在聊天框发一条消息 | 焦点已在输入框 → 直接 `type_text(text="…", submit=true)`；不在就先点一下输入框（**自动回车发送，不要点发送按钮**） |
| 拖拽 / 滑动 / 长按 | 全部用 `click(action="drag" / "swipe" / "long_press", …)`，不要拆成「点击+移动+点击」 |
| 组合键 | `key_press(key="ctrl+shift+s")`、`key_press(key="win+ctrl+d")`、`key_press(key="ctrl++")`（放大） |

四条铁律：

1. **先 `screen_shot(mode="full")` 看一眼任务栏和当前前台，再决定点哪里** —— 不要靠猜坐标。
   **调出已在运行的应用，优先点任务栏底部那个图标**（`taskbar_open(index=N)`），不要先 `open_app`。
   坐标类工具（click/drag/type_text/scroll）**没有新鲜截图基准会直接拒绝执行**，
   截图基准超过 5 分钟也会要求重截 —— 这是插件强制的，不是建议。
2. **已经在前台就不要再切**：`taskbar_open(name="…")` / `open_app` 的返回会直接告诉你
   「已在最前」，此时立刻截图开始操作，**不要反复调 open_app / manage_window 置顶**。
3. **先看焦点再打字**：焦点已经在输入框（`screen_info` 的「键盘焦点」会说明）就直接
   `type_text(..., submit=true)`，**不要再点输入框**；焦点不在才点一下输入框。
4. **要精准就点编号，不要抄坐标**：`refine_point` 之后用 `click(cand=编号)`。
   手抄 x/y 是「点偏」的主要来源之一（抄错一位没有任何反馈），编号的坐标是插件按候选
   落点（质心）算出来的。

## 何时使用

- 用户要求「帮我操作电脑/点开某个软件/在界面上完成某件事」，且内置工具（文件、命令、浏览器）无法完成时。
- 目标只能通过图形界面完成（安装向导、桌面应用、系统设置、需要看界面判断的操作）。
- 能在命令行/文件工具里完成的，优先用那些工具（更快更稳），不要用界面操控绕路。

## 第一步：打开可视化界面（必须，且必须先做）

1. 调用 `web_url` 取得本地可视化地址；
2. 用 **`preview_open(url=该地址)`** 在**用户默认浏览器**里打开 —— 用户要能实时看到画面、
   操作日志，并随时接管；
3. 整个任务期间保持该页面打开；任务结束时告诉用户可以在页面上回看操作过程。

> **这里绝对不要用 `browser_open`。** `browser_open` 是**元素级网页自动化**（另起一个
> 独立浏览器实例、走 CDP 操控 DOM），跟"给用户看一眼可视化界面"是两件事：
> 用它会多开一个浏览器、把工具集带偏到浏览器自动化，甚至让 AI 拿 `browser_click`
> 去点桌面应用 —— 这正是"输入控制电脑 GUI 的提示词却调起了浏览器操控"的原因。
> 一句话记牢：**桌面操控任务全程不碰 `browser_*` 系列工具**（`preview_open` 除外，
> 它不是浏览器自动化，只是"用默认浏览器打开一个网址"）。

## 核心原则：坐标定位五步闭环

**这是本插件最重要的使用纪律。** 每一个界面动作都走这五步，不要跳步：

| 步 | 做什么 | 工具 |
| --- | --- | --- |
| ① 看 | 截一张图，看清界面上有什么、目标在哪 | `screen_shot`（`mode=window` 只看目标窗口） |
| ② 量 | 放大局部、把「目标」变成精确的像素坐标 | `zoom_in`（小目标必用，放大后接近 1:1 读数最准） |
| ③ 修 | 把估的坐标**吸附到控件落点（质心）**；列表场景读「行标尺」挑对行；**密排界面按编号挑目标** | `refine_point` |
| ④ 点 | 按编号或坐标点击/拖拽/输入（用 ③ 挑的编号最稳；手填坐标要带 `snap=false`） | `click(cand=N)` / `click` / `drag` / `type_text` / `scroll` … |
| ⑤ 验 | **重新截图确认结果**，再进行下一步 | `screen_shot`（或 `click(verify=true)` 自动比对） |

为什么必须这样：坐标是唯一的信息来源。跳过 ① 就是在猜，跳过 ⑤ 就是在盲走 ——
这两件事合起来就是「点了半天什么也没发生，还越走越远」的根本原因。

**为什么要有 ③ 这一步**：屏幕被缩成 1280 宽的图发给你，图上 1px 的估计误差在 4K 屏上
就是 3px；而 Blender / 剪辑软件里按钮只有 20px 高，差 3px 就点到隔壁。`refine_point`
用纯像素算法抹掉这个误差，并回一张放大对照图给你确认。**`click` 默认也会做同样的吸附**，
所以熟悉之后可以省略 ③ 直接点；但第一次操作某个界面、或点了没反应时，务必用 ③ 看图。

**截图调用策略（怎么截最省又最准）**：

1. **优先截窗口，不截全屏**：`screen_shot(mode="window", hwnd=…)` 只看目标窗口。
   窗口 ≤1280 宽时是 **1:1**，图上读数就是屏幕坐标，误差不放大；图也更小、更省 token。
   整屏截图会把 1920（或更宽）压到 1280，误差被放大 1.5 倍以上，只有「先看任务栏/
   全局布局」时才值得用。
2. **整屏截图被缩放时，按返回文字里的提示做**：它会直接告诉你前台窗口的 hwnd，
   改截那个窗口即可，不用自己猜。
3. **小目标先放大再读数**：`zoom_in(x, y)` 把局部放到大图，最近邻放大后图上像素与
   屏幕像素一一对应；在全屏缩略图上硬估小图标是「点偏」的主要来源。
4. **任务栏图是纯净原图**：`taskbar_open()` 返回的任务栏/面板图片**不带任何标记**
   （不画框、不画编号、不画准星）—— 认图标靠「槽位表的中心坐标 + 原图」对照，
   编号和坐标都在文字表里。
5. **行动后重新截图验证**（第 ⑤ 步），但验证也优先截窗口：变化发生在哪个窗口就截哪个。

**密排界面一定要用 ③ 的「候选菜单」挑编号 —— 这是「点偏」最常见的真凶。**
吸附只会挑**离你估计点最近**的那一个目标。Blender 工具栏、剪辑软件属性面板、一排小图标
这种按钮密排的界面上，估计点只要偏几像素，「最近的那个」就是**隔壁按钮** —— 于是
「点偏」变成「稳稳地点错」，而且你根本无从察觉。`refine_point` 会把这一片里所有像控件的
目标**编号框出来**，并列出它们各自的屏幕坐标：

```
候选目标（本区域共 9 个，按离你的估计点由近到远；下图已用青色方框编号框出，
当前选中的那个是洋红色）：
  1. 行  中心(120,287)  尺寸 43×13  距估计点 13px   ← 当前选中
  2. 行  中心(120,317)  尺寸 51×11  距估计点 17px
  3. 块  中心(93,317)  尺寸 13×12  距估计点 24px
```

拿到编号之后：**优先 `click(cand=编号)`** —— 坐标由插件按该候选的落点（质心）算出，
你只要认编号，不用抄数字（抄错一位没有任何反馈，这是「点偏」的隐形来源）。
也可以 `refine_point(x, y, pick=N)` 改选，或手动
`click(x=<表里的 x>, y=<表里的 y>, space="screen", snap=false)`；
**手动点一定要带 `snap=false`** —— 否则 `click` 会再吸附一次，又可能被挪回隔壁那个去。

**列表要点第几行，靠 ③ 给的「行标尺」量，不要靠眼睛数。** 碰到列表（联系人、会话、
消息、菜单、表格）时，`refine_point` 会把这一片按 y 投影切出**一条条横向内容带**，
直接告诉你每一条带的中心 y（屏幕物理坐标），例如：

```
行标尺：本区域检测到 3 条横向内容带，中心 y = 135 / 199 / 263（屏幕物理坐标）。
你给的 y 落在第 2 条带上；要点别的行就换用对应的 y。
```

这是**纯几何数字**，不含元素名也不含可点信息 —— 你可以直接**按数字选行**，然后
`click(x, 199, space="screen")`。这比「看放大图数第几行」可靠得多，因为数行是视觉
判断，而标尺是量出来的。

**坐标精度保障**（四个工具分别解决四个环节，别混用）：

- `refine_point(x, y)` —— 把估计坐标**吸附到附近控件的落点**，并把这一片所有候选
  **编号列出**（中心/尺寸/距离），回放大图（青色方框=候选编号、黄色准星=你的估计点、
  洋红方框=当前选中、绿色准星=最终目标点）。列表场景额外给**行标尺**：每一条横向内容带
  的中心 y（纯数字），让你**按数字选行**。**密排界面必须用它挑编号**，不要指望吸附猜中。
  附近没有可信元素时**原样返回并说明**，不会乱改。这是解决「点不准」的主力工具。
- `verify_point(x, y)` —— 验证**整条链路**：把图像坐标换算成屏幕物理坐标、真的把光标
  移过去、再回读真实落点，报告偏差。看到「偏差 (+0,+0) ✓ 完全一致」才说明
  「截图坐标 → 物理坐标 → 鼠标落点」这条链路是准的。它**不做吸附**，只验链路。
- `click(..., verify=true)` —— 点击后**比对落点附近像素**，直接告诉你「界面已响应」
  还是「完全没有变化」。这是抓「点了没反应」这类静默失败最省事的办法。
- `click_window(hwnd, rel_x, rel_y)` —— 用**窗口相对坐标**点击。窗口挪了也不会点错，
  适合反复操作的同一个窗口。

**截图是纯净原图**：`screen_shot` / `zoom_in` 返回的图像**不叠加坐标网格、刻度或准星**，
直接看图判断目标位置即可（只有需要网格辅助读数时才显式传 `grid=true`）。

**坐标系与换算**：所有工具的 x/y 默认都是**图像像素坐标**（图像左上角为 0,0），插件自动
换算成屏幕物理坐标。每次截图返回的文字里都写着**精确换算公式**（原点 + 缩放比），
例如 `屏幕物理 = (0,0) + 图像坐标 × (1.5000,1.5000)` —— 缩放比大于 1 就说明图被缩小了，
读数误差会被放大同样的倍数，小目标务必先 `zoom_in`。若你手里已经是**物理坐标**
（上一轮返回值、`list_windows` 的窗口位置），传 `space="screen"` 让插件别再换算一次。


## 第 0 步：先 `screen_shot` 看一眼任务栏 —— 图标在就直接点

**这是本插件最容易被违反、代价最大的一条纪律。**

用户说「打开微信」「切到微信」「微信在后台」「微信最小化了」时，**不要上来就 `open_app`，
更不要 `list_windows` 循环**。按下面的顺序，通常 1~2 次调用就到位：

```
① screen_shot(mode="full")          ← 一张整屏图同时回答三件事：
                                      任务栏在哪、图标在不在、现在前台是什么
② 图标在任务栏可见区 → taskbar_open(index=N)
③ 图标不在可见区     → taskbar_open(where="panel")     ← 右侧「↑」里的隐藏图标/后台应用
④ 任务栏和面板都没有 → open_app(name="…")               ← 兜底：启动/恢复/置顶
```

**为什么任务栏优先于 `open_app`**：应用已经在跑时，点任务栏图标是**一步切过去**，
而 `open_app` 要先找窗口、判断是否最小化、再置顶 —— 慢，而且窗口在别的工作区、
被遮挡、或有两个实例时容易绕圈。`open_app` 仍然是**没运行时的唯一选择**
（未启动的固定图标点下去是「启动」，要等窗口出现，不如 `open_app` 直接给 hwnd）。

**`open_app` 现在是三级优先，返回什么就照着做什么**：

| 它返回的内容 | 说明 | 你下一步该做什么 |
| --- | --- | --- |
| `✅ 已就绪：hwnd=…已在前台` | 窗口已在，已切前台并校验 | 直接 `screen_shot(mode="window", hwnd=…)` 开始操作 |
| 任务栏/面板**原图+坐标表** + 「进程在运行但没有可见窗口」 | 应用最小化到了**托盘**，插件**故意不启动第二实例** | 按坐标表对图认出它的图标 → `open_app(name="…", index=N, where="panel")` |
| 任务栏/面板**原图+坐标表** + 「系统拒绝了前台切换」 | 窗口找到了但抢不到前台（被遮挡/前台锁） | 点它的任务栏图标：`open_app(name="…", index=N)` |
| 报错「没找到名为…的应用」 | 名字对不上，也没在运行 | 从报错里的候选名挑一个重试 |

**不要**在拿到原图+坐标表之后又去 `open_app` / `manage_window` 反复试 —— 那就是绕圈。
确认任务栏和面板里都没有它（且 `open_app` 说进程没在跑），才用 `open_app(name="…", launch=true)` 强制启动。

### `taskbar_open` 怎么用

```
taskbar_open()                      # 只扫描：返回任务栏原图（无标记）+ 每个图标的中心坐标
taskbar_open(index=3)               # 点第 3 个（同时回读落点、核对前台窗口是否真换了）
taskbar_open(where="panel")         # 展开右侧「↑」面板，把里面的图标编号列出
taskbar_open(where="panel", index=2)  # 在面板里点第 2 个
taskbar_open(where="panel", chevron=7) # 自动认错「↑」时，用编号指定它
```

返回里有三样东西要看：

- **任务栏原图**：**纯净无任何标记**（不画框、不画编号、不画准星）。认图标的方式是
  「按槽位表的中心坐标对图看」—— 几何算法已经把每个图标的位置量好了；
- **槽位表**：`1. 中心(916,1057) 尺寸 23×23 应用区`、`7. 中心(1683,1055) 12×7 右侧托盘区`…
  带 **`[已启动]`** 的是正在运行的应用（图标下方有指示条），点它等于切窗口；
- **点击回报**：`落点回读：(916,1057)，与请求完全一致` + `前台窗口已切换：「…」→「…」`。
  如果它说 **`⚠ 前台窗口没有变化`**，说明这一下没落在图标上（或那是未启动的固定图标），
  **不要对着同一坐标重复点**，回到槽位表的坐标核对。

**区段提示要利用**：槽位表会标 `最左区（开始菜单/小组件/搜索）` /
`应用区` / `右侧托盘区（输入法/音量/网络/时钟/↑隐藏图标）`。
要找的应用一般在**应用区**；托盘区那些小图标是输入法、音量、时钟，点错会弹出
无关的菜单 —— 除非你就是要开「↑」面板。

**任务栏是自动隐藏 / 全屏窗口盖住时**，工具会如实说「没在屏幕底部找到任务栏通栏」，
并列出三种可能（自动隐藏 / 全屏遮挡 / 任务栏不在底部）。此时：
把鼠标移到屏幕最下沿停一下再重试，或直接 `open_app`。

### 绝对不要这样做

```
❌ list_windows → 没看到微信 → list_windows 再确认一次 → screen_shot 整屏找
   → manage_window(activate, title="微信") 失败 → list_windows 又来一遍 …
❌ 对着任务栏截图目测一个坐标直接 click —— 任务栏图标只有 20~30px，目测必偏
```

`open_app` 为什么仍然值得信任（它是第 ④ 步）：

- 它**能启动没运行的应用**（`list_windows` 只能看到已经在跑的）；
- 它**会恢复最小化的窗口**（最小化时窗口尺寸是哨兵值 `160×28`、位置在 `-32000`，
  照着这种窗口截图算出来的坐标全在屏幕外，怎么点都点不中）；
- 它**会实测校验真的切到了前台**，切不到会如实告诉你原因，而不是让你以为成功了；
- 它**直接给出 hwnd**，后面 `screen_shot(mode="window", hwnd=…)` 直接用。

拿到 hwnd 之后就**不要再回头调 `list_windows`**。若确实需要看全景（比如要确认
弹了哪个对话框），`list_windows` 调**一次**就够，它的输出里带「最小化」标记。

## 标准流程

1. `screen_info`：确认分辨率、当前前台窗口、接管状态；
2. **打开目标应用，二选一（顺序很重要）**：
   - 应用**可能已经在跑**（微信/浏览器/编辑器/Blender 这类常驻的）→ 先 `screen_shot(mode="full")`
     看任务栏有没有它的图标，有就 `taskbar_open(index=N)` 一步切过去；
     没有就 `taskbar_open(where="panel")` 翻右侧「↑」的后台面板；
   - 都没有 / 不确定 → **`open_app(name="目标应用")`**：没运行会启动、最小化会恢复，
     并实测确认已切到前台，直接给 hwnd。
   **两种情况都不要用 `list_windows` 找窗口**；
3. `screen_shot(mode="window", hwnd=…)`：**建立坐标基准** —— 之后所有坐标都以这张图为准；
4. 需要看清细节就 `zoom_in(局部)`，把目标位置量准（小目标务必放大到接近 1:1）；
5. 动手前用 `refine_point(x, y)` 把坐标**吸附到控件落点（质心）**并看对照图确认；
6. 行动：`click` / `type_text` / `scroll` / `key_press` …
   - **鼠标动作统一走 `click` 的 `action`**：`click(action="drag", x, y, x2, y2)` 拖拽、
     `action="swipe"` 滑动、`action="long_press"` 长按、`action="select"` 拖选、
     `action="double"` 双击、`action="right"` 右键。**不要**把拖拽拆成「按下+移动+松开」；
   - **发消息用 `type_text(text="…", submit=true)`**：输入完成自动回车发送，不必再点发送按钮；
   - **组合键直接写在 `key_press(key=…)` 里**：`ctrl+shift+s`、`win+ctrl+d`、`alt+f4`、
     `ctrl++`（放大）、`ctrl+-`（缩小）；
   - 拿不准坐标链路就先 `verify_point`；想自动判断是否点生效就传 `verify=true`；
     操作三维视口/画布/时间轴这类内容区时传 `snap=false`；
7. **行动后必须重新 `screen_shot` 验证**（对话框是否弹出、内容是否输入正确），再进行下一步。

**坐标约定**：`click`/`drag`/`screen_shot`/`zoom_in`/`verify_point`/`refine_point` 的 x/y
都使用**当前截图基准的图像像素**（图像左上角为 0,0），插件自动换算为屏幕物理坐标 ——
不要把截图坐标再手动乘以缩放比例。若你手里已经是**物理坐标**，传 `space="screen"` 跳过换算。
**例外**：`click_window` 的 `rel_x`/`rel_y` 是**窗口截图上的像素坐标**（即你在
`screen_shot(mode="window")` 那张图上读到的位置；窗口被缩放过也会按缩放比换算）。

## 看不到的窗口：桌宠 / 悬浮球 / 托盘浮层

有些目标**没有窗口标题**（或标题是程序名而非界面名），且不在任务栏里 ——
桌宠、悬浮球、贴边工具条都属于这类。`list_windows` 会把它们一并列出，
类别标为 **`工具型浮层（桌宠/悬浮球）`**（判据是窗口扩展样式 `WS_EX_TOOLWINDOW`，
不是「有没有标题」—— PyQt 之类会把程序名自动设成标题，靠标题判会漏掉）。

处理这类目标：

1. `list_windows` 找到它（看 `<工具型浮层>` 那一类，用 `process`/`class`/尺寸认准）；
2. `screen_shot(mode="window", hwnd=它)` 看它长什么样、要点的东西在哪个像素位置；
3. `click_window(hwnd=..., rel_x=..., rel_y=...)` 用**窗口相对坐标**点击
   （相对窗口左上角，窗口移动也不会点错）。

## 右键菜单：菜单是独立窗口

右键弹出的菜单是一个**独立的顶层窗口**，不属于触发它的窗口的子树。

标准做法（全程坐标）：

1. 在**目标窗口的截图**上读出要右键的位置；
2. `click(x, y, button="right")` 或 `click_window(hwnd=..., rel_x=..., rel_y=..., button="right")`
   呼出菜单；
3. **重新 `screen_shot`**：菜单是新的顶层窗口，它在原窗口截图里可能看不到 ——
   用 `screen_shot(mode="full")` 截全屏，或先 `list_windows` 看 `<弹出菜单>` 那条
   拿到菜单窗口的 hwnd，再 `screen_shot(mode="window", hwnd=菜单hwnd)`；
4. 在菜单截图上读出目标菜单项的像素位置 → `click` 点它。
5. 点完**再截一次图**确认菜单已消失、动作已生效。

> 实例：关闭桌宠小猫 = `list_windows`（找到工具型浮层）→
> 截图定位到小猫 → `click_window(hwnd=桌宠, rel_x=…, rel_y=…, button="right")`（呼出菜单）→
> 截全屏看菜单 → 读出「退出」的位置 → `click` 点掉 → 截图确认窗口已消失。

## 「第 N 个」和「发文件」这类指令怎么做准

这两类指令是最容易翻车的地方，各有专门的做法。

### 点「第 N 个 / 第 N 个人 / 第 N 项」

列表项**没有任何结构化信息**，而「点偏一行」是这类任务最常见的失败。**核心纪律：
用 `refine_point` 的「行标尺」按数字选行，不要用眼睛数行。** 数行是视觉判断，会错；
标尺是量出来的，不会错。

1. `screen_shot(mode="window", hwnd=目标窗口)` 拿到图（窗口 ≤1280 宽时是 1:1，读数最准）；
2. 目测目标大概在哪一行，给一个**粗略**坐标（差一两行没关系），调
   `refine_point(x, y)`；
3. 读返回文字里的 **`行标尺`** 一行 —— 它列出本区域每条内容带的中心 y，并按顺序编号；
   想点第 N 行就取第 N 个 y。若返回里出现
   **「⚠ 你给的 y 不在任何一条带上」**，说明你给的 y 正落在两行之间的空隙里 ——
   这正是「点偏」最典型的原因，务必换成标尺里的某个 y；
4. `click(x, y_N, space="screen")` 点它 —— 标尺给的已经是**物理坐标**，用
   `space="screen"` 让插件别再换算一次。吸附默认开着也无妨（那个 y 本来就是行中心，
   不会被改动）；想要严格照测量值点就传 `snap=false`；
5. `screen_shot` 确认点开的是不是目标（或 `click(verify=true)` 自动比对）。

**行标尺只覆盖当前搜索范围**（默认 `reach=88`，即估计点上下各 88px）。列表很长时，
先滚动到目标附近、或用 `zoom_in` 看清大致位置，再让标尺把**视野内**的每一行量准。
要一次看到更多行，把 `refine_point` 的 `reach` 调大（上限 140）。

**非列表的密排界面，改用候选菜单**（工具栏、属性面板、一排小图标）：那里没有「第 N 行」
可数，但同样有「偏一点就点到隔壁」的问题。做法是看 `refine_point` 返回的
**候选目标**表（编号 / 中心 / 尺寸 / 距离），在图上认出你要的那一个，然后
`refine_point(x, y, pick=N)` 或 `click(x=<表里的 x>, y=<表里的 y>, space="screen", snap=false)`。
注意**改选后一定要带 `snap=false`** —— 不带的话 `click` 会再吸附一次，又可能被挪回去。

**为什么 x 不用管**：列表整行都可点，所以吸附**只对齐 y、不动 x** —— 你给的 x 落在
行内空白处也照样能点中（返回值会写明「x 保持你给的位置」）。反过来，工具条上并排的
按钮则必须留在你指的那个按钮上，算法也确实是这么做的（不会被整条带的中心拽走）。

**稳妥做法：能用搜索框就不要数行。** 如果用户给的是一**个名字**而不是「第几个」，
走搜索框远比数行可靠：点搜索框 → `type_text("张三")` → 等结果 → 点第一行。

### 把某个文件发给某个会话

**不要从桌面上拖图标** —— 拖拽要经过「悬停触发、拖动、落点命中」多个易错环节。
稳妥的做法是**用文件工具把路径查准，再用文件对话框输入路径**：

1. 用内置的文件/命令工具（不是界面操控）解析出文件的**绝对路径**——比如桌面上
   某个文件就是 `C:\Users\<用户名>\Desktop\<文件名>`。这一步完全不需要 GUI，最可靠；
2. 在目标会话里点「+」→「文件」，打开系统文件选择对话框；
3. 对话框弹出后 `screen_shot` 看清「文件名」输入框的位置 → 点它 →
   `type_text("C:\Users\…\Desktop\某文件.docx")`（**完整路径**）→ `key_press("enter")`。

这样整条链路里唯一的界面操作就是「点两个按钮 + 输一个路径」，全是可验证的精确动作。

## 面对复杂桌面的处理策略

真实桌面远比单窗口复杂，以下情形按此处理：

- **窗口抢焦点**：子窗口/对话框/安装向导常在启动时抢焦点。点击前先
  `manage_window(action="activate")`；工具返回「目标窗口未成为前台」时说明系统拒绝了置顶
  （锁屏/安全桌面/UAC），此时点击可能落空 —— 先处理前置窗口或请用户手动切窗口。
- **弹窗延迟出现**：不要固定 `sleep` 猜测，用 `manage_window(action="wait", title="…")`
  等窗口真正出现，比任何固定等待都可靠。等到了再截图。
- **窗口位置乱飞**：用 `manage_window(action="maximize")` 最大化目标窗口再操作 ——
  最大化后窗口尺寸固定，坐标基准更稳；需要精确坐标时用 `move` 摆好位置。
- **找不到目标窗口**：先 `manage_window(action="state")` 看全部窗口，确认标题再操作。
- **虚拟桌面隔离**：用户要求「别动我的窗口 / 后台静默」时，先
  `open_virtual_desktop(action="new")`，**任务结束必须** `open_virtual_desktop(action="back")` 返回。

## 输入方式：默认鼠标，触控需显式指定

**默认走鼠标注入**（`SendInput` 绝对坐标，已按虚拟桌面归一化并带
`MOUSEEVENTF_VIRTUALDESK`，多显示器也精确）。这是刻意的选择：

> 实测（原生 OpenGL 窗口、125% DPI、带触控数字化仪的本机）——
> **鼠标注入落点偏差 (+0,+0)**；**触控注入偏差在 0~428 像素之间且不可预测**
> （同一进程内多次 tap 的偏差方向与大小都不一致，因为触控要经过数字化仪标定
> 与「触控→鼠标」提升两段坐标变换）。生产级软件（Blender/CAD/剪辑）的按钮
> 常常只有十几像素宽，触控的偏差等于「点了但点错地方」——比点不到更危险。

确实需要触控语义时（触控优先的 UI），在 `click`/`click_window`/`long_press`/
`drag`/`swipe`/`select` 里显式传 `input="touch"`；触控注入失败会自动
回退鼠标。`screen_info` 会如实报告当前用的是哪种注入方式。

## 生产级复杂软件（Blender / CAD / 3D / 剪辑）

这类软件是 **GPU 自绘界面**，连截图都可能抓不到 —— 正好是本插件的主场，因为
坐标方案对「有没有控件信息」完全不敏感。按下面的纪律做，才能做到精准：

1. **先截图**：`screen_shot(mode="window", title="Blender")`。窗口图是后续坐标的唯一基准。
   窗口宽度不超过 1280 时是 **1:1 原生分辨率**（返回文字里会写明「1:1」），此时图上读到的
   像素就是屏幕像素，最准；整屏截图则会被缩小，务必看换算比。
2. **小目标先放大**：工具栏图标常常只有十几像素，`zoom_in` 放大到接近 1:1 再看。
   放大走**最近邻**，边缘是硬实的像素方块，可直接按像素读数。
3. **点击前吸附，并按编号挑目标**：`refine_point(x, y)` 会把坐标修正到最近控件的落点（质心），
   并回一张放大对照图（黄=你的估计、绿=吸附点）。**第一次操作某个界面时务必看这张图**，
   确认它吸到了你想点的那个控件上。`click` 默认也会做同样的吸附（返回值里会说明位移）。
   工具栏 / 属性面板这种**按钮密排**的界面，只用吸附是不够的 —— 估计偏几像素，「最近的
   那个」就是隔壁按钮。所以要看它给的**候选菜单**，用 `pick=N` 改选，或直接
   `click(x=<表里的 x>, y=<表里的 y>, space="screen", snap=false)`。
   ⚠️ 三维视口 / 画布 / 时间轴这类**内容区**没有「控件」可言，吸附可能把你带到附近的
   图标或文字上 —— 在这些区域操作请传 `snap=false`，用精确像素。
4. **先自检**：`verify_point(x, y)` —— 它会真的把光标移过去再回读真实落点，报告偏差。
   看到「偏差 (+0,+0) ✓ 完全一致」再动手；有偏差就先重新截图刷新基准。
   它是**链路自检**，不改变坐标，和上面的吸附各管一段。
5. **点击时带上校验**：`click(x, y, verify=true)` 会在点击前后逐像素比对落点附近，
   直接告诉你「界面已响应」还是「完全没有变化」。**看到「没有变化」不要盲目重试同一坐标**，
   先重新截图确认界面状态（可能是窗口没激活、被遮挡、或坐标基准过期）。
6. **窗口移动过就用窗口相对坐标**：`click_window(hwnd=..., rel_x=..., rel_y=...)`，
   rel 坐标就是你在**窗口截图**上读到的像素位置（窗口挪了也不会点错），同样默认吸附。
7. **拖拽/框选**用 `drag`（按下后有停顿、分步数足够、末步精确归位），
   Blender 的框选、拉滑块、拖参数都靠它；`scroll` 用于滚轮缩放/平移视图。
   拖动**视口内容**（旋转视角、移动物体）时传 `snap=false`。
8. **大量操作前先把窗口最大化并激活**（`manage_window(action="maximize")`），
   坐标基准更稳定，也避免被其他窗口盖住导致点击落空。

**截图抓不到内容时**：极少数 GPU 界面（独占全屏、硬件叠加层）会让 PrintWindow
返回空白。插件会**自动检测空图并改用屏幕抓取**（会先把窗口激活置顶），返回文本里
会写明「抓取方式：屏幕抓取」；此时操作期间不要让其他窗口盖住它。也可手动指定
`screen_shot(capture="screen")` 强制走屏幕抓取。

**键盘同样重要**：Blender 等软件的很多操作用快捷键比点按钮更稳（`G/R/S` 变换、
`Tab` 切模式、`Numpad` 切视图、`Ctrl+Z` 撤销）。能用快捷键的优先用 `key_press`，
把鼠标点击留给确实只能点的目标（工具栏图标、视口操作、拖拽）。

## 点不准怎么排查（坐标精度手册）

「点不准 / 点了没反应」几乎总是下面五件事之一。**按顺序排查，不要凭感觉重试同一坐标**：

| 现象 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| **点列表总是点偏一行**（联系人、会话、消息、菜单） | 模型是「估」第几行在哪里的，眼睛数行会错；且行内空白区离内容很远时旧算法根本无从吸附 | 用 `refine_point` 的 **`行标尺`** 按**数字**选行，再 `click(x, y_N, space="screen")`。出现「⚠ 你给的 y 不在任何一条带上」就说明 y 落在两行之间的空隙里 —— 必须换成标尺里的 y |
| 点偏了几像素，点到隔壁控件/边缘 | 图上估计有误差，且截图被缩小放大了误差 | `refine_point` 吸附到控件落点；小目标先 `zoom_in` 放大到 1:1 再读 |
| **按钮密排的界面（工具栏/属性面板/一排图标）总是点错** | 吸附只挑**离你最近**的那一个：估计偏几像素，「最近的那个」隔壁控件，于是「点偏」变成「稳稳地点错」，且你无从察觉 | **用 `refine_point` 的候选菜单按编号挑**：`refine_point(x, y, pick=N)`，或直接 `click(x=<表里的 x>, y=<表里的 y>, space="screen", snap=false)`。**改选后点必须带 `snap=false`** |
| 点在正确位置但「没反应」 | 窗口没激活 / 被遮挡 / 控件禁用 | 看 `click` 返回值里的遮挡提示；`open_app` 或 `manage_window(action="activate")` 后重试；`click(verify=true)` 确认 |
| 整体偏移一个固定量 | 坐标基准过期（又截了别的图/窗口动过） | 重新 `screen_shot` 同一目标刷新基准；或改用 `click_window` 的窗口相对坐标 |
| 偏差随位置变大（越靠右下越偏） | 缩放比不是 1（整屏截图被缩小） | 看返回文字里的换算公式；改用 `mode="window"` 截图（窗口 ≤1280 宽时是 1:1） |
| 明明坐标对，光标也到位，就是点不中 | 目标是 GPU 自绘界面，坐标需要像素级精确 | 传 `snap=false` 用精确像素；或用 `key_press` 走快捷键（Blender 类软件更稳） |
| **点任务栏图标点偏 / 点了没反应** | 任务栏图标只有 20~30px，且相邻图标之间只有 6~8px 缝；目测坐标必然落在缝上或隔壁图标上 | **不要目测**。`taskbar_open()` 会给每个图标编号 + 精确中心坐标，直接 `taskbar_open(index=N)` 一步点掉（点完自动回读落点、核对前台窗口） |
| **任务栏里找不到那个图标** | 图标被折叠进右侧「↑」的隐藏图标/后台应用面板 | `taskbar_open(where="panel")` 展开面板并编号；`taskbar_open(where="panel", index=N)` 一步点掉 |
| 工具说「没在屏幕底部找到任务栏通栏」 | 任务栏设了自动隐藏 / 有全屏窗口盖住 / 任务栏不在底部 | 把鼠标移到屏幕最下沿停一下再重试；或直接 `open_app(name="…")` |

**吸附什么时候要关掉**：`click` / `drag` / `long_press` 默认吸附（`snap` 默认开），
`swipe` / `select` 默认不吸附。**在这三种情况下请显式传 `snap=false`**：

1. **三维视口 / 画布 / 时间轴 / 视频预览**这类内容区 —— 那里没有「控件」，吸附可能把你
   带到附近的图标或文字上；
2. 需要**像素级精确**的位置（对齐参考线、取色、画布上某个点）；
3. 吸附**吸错了目标**（返回值里写了位移多少，对照 `refine_point` 的图能看出来）。

**吸附为什么是安全的**：它只在「附近确实有一个像控件的连通域」时才动手 —— 纯背景、
渐变壁纸、照片、噪点都不会被误判成元素（算法会原样返回）。而且它**绝不会**把点击带到
很远的地方（位移有上限），返回值里也一定写明「吸附了没有、位移多少、依据是什么」。

**换算公式每次都会给你**：截图返回的文字里带一行
`坐标换算：屏幕物理 = (原点) + 图像坐标 × (缩放比)`。缩放比不是 1 就说明图被缩小了 ——
**误差会被放大同样的倍数**。看到 `× 1.50` 或更大，就该先 `zoom_in` 再读数。
若你手里已经是物理坐标（上一轮返回值、`list_windows` 的位置），传 `space="screen"` 直接给。

**每一次 `click` 都会回读真实落点并报告**：返回值里有
「落点回读：(x,y)，与请求完全一致（注入链路 0 偏差）」。鼠标注入的归一化公式与 Windows
的回程换算互为逆运算，正常情况偏差就是 0；一旦看到「⚠ 光标实际在 …」的警告，说明注入
链路有偏差（多屏归一化 / DPI 缩放），此时**先跑 `verify_point` 自检**，不要盲目重试。

## 真实任务最容易失败的坑（都踩过，务必按此处理）

**坑 1：截图能穿透遮挡，鼠标点击不能。**
窗口截图走 `PrintWindow`，**窗口被别的窗口盖住也照样能截到内容**；但鼠标点击只会落到
**该点最顶层的窗口**上。于是「照着截图点」时，若目标窗口被盖着，点击就打到了遮挡窗口上 ——
目标界面毫无变化，任务却以为自己点过了。
插件已在坐标点击前**自动把目标窗口激活置顶**（必要时用临时置顶绕过前台锁），并在返回值里
说明；但看到这类提示时要意识到「刚才有窗口遮挡」，若紧接着报「没有变化」，多半是没抢到前台。
此时请用户手动切一下窗口，或 `manage_window(action="activate")` 后重试。

**坑 1.5：键盘注入只认「前台窗口」——文字会打进别的应用（最危险）。**
`SendInput` 的键击没有目标概念，只发给**当前前台窗口**。所以「照着只截该窗口的截图操作」时，
若点击没能把焦点交给目标窗口，随后的 `type_text` / `enter` 就会打进**当前前台应用**
（最糟的情况是 AI 助手自己的输入框，等于把消息发错了地方）。
插件现在会在**每次键盘注入前**确保目标窗口在最前（目标 = 显式 `title`/`hwnd`，或最近一次
窗口截图的那个），抢不到焦点就**直接拒绝执行**并说明原因；`type_text` / `key_press` 的返回值
还会写明「注入时前台窗口：X」，方便你立刻核对。
**你也要配合**：键盘输入前先确认「目标窗口已在前台」——先 `click` 把焦点交过去，
再输入；看到返回值里前台窗口不是目标窗口，**立刻截图核对，不要重复输入**
（重复输入会把消息发两遍）。

**坑 1.8：最小化窗口的截图是「废图」，照着它算的坐标全在屏幕外。**
窗口最小化后 `GetWindowRect` 会返回 `(-32000,-32000,160,28)` 这种哨兵值，PrintWindow
也只会给出一张 160×28 的空图 —— 但看起来「截图成功了」。照着这张图算坐标，点击永远
落不到目标上（实测踩过：微信最小化时反复点不中目标用户，就是这个原因）。
**正确做法：先 `open_app(name="微信")`** —— 它会恢复最小化的窗口并实测确认已到前台，
直接给你可用的 hwnd。截图工具自己也会**自动恢复**并在返回值里说明；恢复不了则
**直接拒绝截图**，让你先 `manage_window(action="restore")`。
`list_windows` 里窗口标注了「最小化」的就是这种状态，别对着它算坐标。

**坑 1.9：不要「自己找窗口」——这是任务绕不出来的头号原因。**
微信在后台 / 最小化 / 根本没启动时，模型的典型失败模式是：
`list_windows` 找不到 → 再 `list_windows` → `screen_shot` 整屏找 → `manage_window(activate)`
失败 → 又 `list_windows` …… 十几次调用过去，任务毫无进展，用户只看到「疯狂调用工具找位置」。
**根治办法只有一个：第一件事就 `open_app(name="微信")`。**
它一次就把「没运行就启动 / 最小化就恢复 / 切到前台 / 实测校验」全做完，并返回 hwnd。
拿到 hwnd 后**不要**再回头调 `list_windows`。
另外：**同一个失败动作不要连试两次以上** —— 第二次失败就说明前提假设错了
（名字不对 / 应用没装 / 窗口在别的虚拟桌面），先换思路或 `ask_user`。

**坑 2：点了没反应，往往不是坐标错，而是窗口没激活。**
坐标完美但界面毫无变化 —— 九成是焦点不在目标窗口上，点击被别的窗口吃掉了。
顺序排查：① 看 `click(verify=true)` 的返回，确认是「没有变化」；
② `manage_window(action="activate", hwnd=…)` 把目标窗口提到前台；
③ 重新 `screen_shot` 刷新坐标基准（窗口可能动过）；
④ 再点一次。**不要**在原坐标上连着点第二遍。

**坑 3：按钮文字/图标位置会随主题与语言变。**
同一个按钮在不同主题、不同语言、不同缩放比例下位置都不一样。
**每一次都重新截图定位**，不要复用上一次任务里的坐标（哪怕是同一个软件）。
窗口大小变过（最大化/还原）一定要重新截图。

**坑 4：窗口句柄会变。**
同一个应用的登录窗口与主窗口是**不同的 hwnd**，窗口还可能被重建。
每一步操作前重新 `list_windows` / `screen_shot` 拿最新句柄，不要复用上一步的 hwnd
（报「未找到目标窗口」时就是句柄过期了）。

## 复杂任务剧本：微信（发消息 → 发文件 → 引用消息）

用户会这样下指令：「打开微信，给第二个人发你好，然后把桌面上的某文件发给第三个人，
再引用他说的那句话回复他」。下面把这条链拆成可验证的步骤 —— **每一步都要用截图确认后再走下一步**。

### 第 0 步：打开微信（先看任务栏，再 open_app）

```
screen_shot(mode="full")          # ① 先看一眼：微信图标在不在任务栏
taskbar_open(index=N)             # ② 在 → 一步切过去（带「已启动」的就是在跑的微信）
taskbar_open(where="panel")       # ③ 不在可见区 → 展开「↑」隐藏图标/后台应用面板找
open_app(name="微信")             # ④ 都没有 → 启动/恢复并置顶，直接给 hwnd
```

微信已经在跑（最常见）时走 ② 最快：**一次调用**就切到前台，还能顺便确认
「前台窗口已切换：「…」→「微信」」。**这一步之后不要再调 `list_windows` 找微信。**

- 如果返回的是**登录窗口**（很小、类名 `Qt…QWindowIcon`）：`screen_shot` 看这个登录窗口，
  找到「进入微信」按钮的像素位置 → `click` 点它。
  （用户说「登录」但按钮上写的是「进入微信」—— **按截图上的实际文字找位置，不要凭印象**。）
- 出现二维码时：**必须让用户用手机扫码**，这是安全边界，不要尝试绕过。
- 登录后窗口句柄会变（登录窗口 → 主窗口），**重新 `open_app(name="微信")`** 拿新 hwnd。

### 第 1 步：定位「第 N 个人」

微信主窗口**没有任何结构化信息**，列表项只能靠视觉定位：

1. `screen_shot(mode="window", hwnd=微信hwnd)` → 从图上读出左侧聊天列表的区域；
2. `zoom_in` 把该区域放大 → 一行一行看清楚，数准「第 2 行」是谁（这一步不能省，
   数错就发错人）；`zoom_in` 的返回值会给出放大图与原图的坐标换算关系；
3. 把该行**垂直居中**的位置换算回原图坐标 → `click(x=…, y=…, verify=true)`；
4. **截图确认右侧会话区已经切到你要找的那个人**（看聊天记录/名字），再往下走。

> **优先用搜索框**：如果用户给的是**名字**而不是「第几个」，走搜索框远比数行可靠 ——
> 微信主窗口左上角有搜索框，点它 → `type_text("张三")` → 稍等 → 点搜索结果第一行。

### 第 2 步：发消息

1. **先看焦点**：`screen_info` 的「键盘焦点」一行会直接说焦点是不是在输入框里。
   - **已在输入框 → 直接 `type_text("你好", submit=true)`**，不要再去点输入框
     （多点一次可能点偏、或把焦点挪走，反而发不出去）；
   - 不在输入框 → `screen_shot` 读出底部输入框位置 → `click` 点它 →
     截图确认光标已经在输入框里；
2. `type_text("你好", submit=true)` —— 输入完成自动按 Enter 发送；
3. 少数应用把发送键改成 Ctrl+Enter：此时用 `type_text("你好")` +
   `key_press(key="ctrl+enter")`；
4. `screen_shot(mode="window", hwnd=微信hwnd)` 确认**消息气泡已出现在右侧**。

### 第 3 步：把桌面文件发给「第三个人」

**不要从桌面拖图标**（拖拽要过「悬停触发 → 拖动 → 落点命中」多个易错环节）。
用「文件对话框 + 完整路径」：

1. **先用文件工具解析出绝对路径**（这一步完全不需要 GUI，最可靠）：
   桌面文件就是 `C:\Users\<用户名>\Desktop\<文件名>`；
2. 重复第 1 步，切到「第三个人」的会话（并截图确认）；
3. 截图读出输入框上方「+」的位置 → `click` 点它 → 菜单弹出后**再截一次图**，
   读出「文件」项的位置 → `click` 点它 → 打开**系统文件选择对话框**；
4. 对话框弹出后 `screen_shot` 看清「文件名」输入框 → `click` 点它 →
   `type_text("C:\Users\…\Desktop\某文件.docx")` → `key_press(key="enter")`；
5. 微信会弹发送确认框 → `list_windows` 看有没有新窗口，有就截图定位并点「发送」；
6. `screen_shot` 确认文件卡片出现在会话里。

### 第 4 步：引用某条消息

「引用」= 对某条消息**右键 → 菜单里选「引用」** → 输入框上方出现被引用的原文 →
再输入回复并发送。

1. `screen_shot(mode="window", hwnd=微信hwnd)` → 读出要引用的那条消息的像素位置；
2. `click(x, y, button="right")` 右键那条消息；
3. **菜单是新弹出来的顶层窗口** → `screen_shot(mode="full")` 截全屏看到它，
   或 `list_windows` 找到 `<弹出菜单>` 拿 hwnd 后单独截图；
4. 在菜单截图/全屏图上读出「引用」项的像素位置 → `click` 点它；
5. 截图确认输入框上方出现「引用的原文」→ 点输入框 → `type_text("回复内容")` →
   `key_press(key="enter")`；
6. `screen_shot` 确认回复已发出且**带引用块**。

### 通用纪律

- **每一步都截图确认再走下一步**，别一路盲点到底；
- 界面上**同一处失败不要连试两次以上**：第二次失败就说明前提错了
  （坐标基准过期 / 窗口没激活 / 认错了会话），先重新 `screen_shot` 或 `ask_user`；
- 发送类动作**不可逆**（消息发出去就收不回）——发送前务必确认「当前会话是不是目标那个人」。

### 另一个例子：打开 QQ 给某人发消息（最短路径）

用户说「打开 QQ 给 XXX 发消息」时，照这个顺序走，通常 3~4 次工具调用就完成：

1. `screen_shot(mode="full")` 看一眼任务栏：QQ 图标在就 `taskbar_open(index=N)`
   —— **优先点任务栏图标把窗口调出来**，不要先 `open_app`、更不要反复 `manage_window` 置顶；
   图标不在可见区就 `taskbar_open(where="panel")`；
2. 窗口起来后 `screen_info` 看「键盘焦点」：
   - **已在输入框 → 直接跳到第 3 步**，不要再点输入框；
   - 不在 → `screen_shot(mode="window")` 找到搜索框/输入框，`click` 一次并截图确认光标在里面；
3. 用户给的是人名：在搜索框 `type_text("XXX")` → 选中搜索结果第一行进入会话
   （或直接在会话列表里点那个人，截图确认右侧标题是 XXX）；
4. `type_text("要说的话", submit=true)` —— **输入完自动按 Enter 发送**，
   不要再移动鼠标去点发送按钮；
5. `screen_shot` 确认消息已出现在会话里。

## 屏幕边缘彩色光环（用户提示）

AI 真正操控桌面（点击/输入/滚动/拖拽/拖窗口等）时，屏幕四边会亮起**彩色流光光环**，
提示「电脑正在被自动操作」。它鼠标穿透、不抢焦点、不挡视线，停止操控后淡出。

- 光环亮起 = AI 正在操作你的桌面，**此时不要抢鼠标**，否则会被判定为「用户接管」；
- 用户抱怨「屏幕边缘闪得慌」→ `aura(action="off")` 关闭；
- 纯查询类工具（`screen_shot`/`list_windows`/`screen_info`/`zoom_in`/`verify_point`）
  **不会**点亮光环。

## 用户打断与接管（硬性协议）

工具结果里出现「用户已接管」或「已被用户暂停」时：

1. **立即停止一切操控**，不要再尝试点击/输入，也不要换坐标重试；
2. 向用户简要汇报：已执行到哪一步、当前界面状态、剩余步骤；
3. 若当时在独立虚拟桌面容器中，提示用户「可自行按 Win+Ctrl+← 返回原桌面，或点可视化界面上的
   「恢复」让我返回」；
4. **只有用户明确说「继续」后**，才可以调用 `control(action="resume")` 清除接管标记并继续；
   用户没说继续时，绝不允许自行调用 resume、也不得用其他工具绕过。
5. 自己判断该把控制权交还用户时（例如需要用户输入密码、做主观选择），主动调用 `control(action="take_over")`。

## 工具速查

**感知（看图 → 取坐标）**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `screen_info` | 环境信息（屏幕/虚拟桌面/输入/吸附能力/换算公式/前台窗口/接管状态） | 无 |
| `screen_shot` | 截屏返回给 AI（**纯净原图**，无网格/刻度/准星）—— 一切坐标的来源 | `mode=full\|window`、`title`/`hwnd`、`grid`、`capture` |
| `zoom_in` | 局部放大精确定位（小目标必用；最近邻放大，可直接按像素读数） | `x`、`y`、`size`、`factor`、`smooth`、`space` |
| `refine_point` | **坐标精修**：把估计坐标吸附到最近控件落点（质心）（列表场景再给**行标尺**），并把这一片所有候选**编号列出**（中心/尺寸/距离）＋放大对照图（青框=候选、黄=估计、洋红=选中、绿=目标） | `x`、`y`、`reach`、`pick`、`space` |
| `verify_point` | **坐标链路自检**（换算物理坐标 + 移动光标 + 回读真实落点与偏差；不做吸附） | `x`、`y`、`move`、`space` |
| `list_windows` | 可见窗口列表（**含工具型浮层与弹出菜单**），拿 hwnd 用 | `kind=main\|menu\|overlay`、`limit` |

**坐标级操作（唯一一类操作方式）**
| 工具 | 用途 | 关键参数 |
| --- | --- | --- |

## 失败处理与降级

- `screen_shot` 报「窗口已最小化，截图不可用」→ 先 `open_app(name=…)` 或
  `manage_window(action="restore")`，**不要**对着哨兵尺寸算坐标（坐标会全错）。
- `screen_shot` 返回的图是空白的 → 该界面是独占全屏/硬件叠加层，插件会自动改用屏幕抓取
  （返回文本会写明）；也可显式传 `capture="screen"`。此时别让别的窗口盖住它。
- `verify_point` 报出非零偏差 → 说明坐标基准过期（截图后窗口动过）或缩放/多屏异常：
  **重新 `screen_shot` 再操作**，不要带着偏差硬点。
- `click(verify=true)` 报「落点附近像素完全没有变化」→ 这一击多半没生效，
  先重新截图确认界面状态（窗口是否激活/被遮挡、目标是否已消失），**不要盲目重试同一坐标**。
- 点击总点不中同一个目标 → 用 `zoom_in` 把它放大，重新量一次坐标；再用 `refine_point`
  看吸附对照图（黄=你的估计、绿=吸附点），确认到底吸到了哪个控件上；
  仍不准就用 `click_window` 走窗口相对坐标（不受窗口移动影响）。
- `refine_point` 说「未吸附」→ 说明附近没有可识别的控件（纯背景/渐变/照片/视口内容）。
  这是**正常结果**，按你的原坐标点即可；若那里确实应该有按钮，说明截图被缩得太小，
  先 `zoom_in` 放大再重新取坐标。
- `refine_point` / `click` 的吸附**吸到了隔壁控件** → 传 `snap=false` 用精确像素，
  或把 `snap_reach` 调小（默认 88，可降到 16~24）让它只在更小的范围内找。
- `refine_point` 报「⚠ 你给的 y 不在任何一条带上」→ 你的 y 落在**两行之间的空隙**里，
  这就是「点偏一行」最典型的原因。换成它给出的行标尺里某个 y 再点（`space="screen"`）。
- `refine_point` 只给出 1 条带、但目标明明是个长列表 → 搜索范围不够（默认上下各 88px）。
  把 `reach` 调大（上限 140），或先 `scroll` 到目标附近再量。
- 报「窗口相对坐标超出窗口范围」→ 先 `list_windows` 核对窗口尺寸，
  或干脆不传 `rel_x`/`rel_y` 点窗口正中心。
- 报「已拒绝点击：落点被 X 盖住」→ 系统拒绝了置顶，点击会落到遮挡窗口上（可能误触别的
  应用），所以插件**没有执行**。请用户手动切窗口，或先 `manage_window(action="minimize")`
  把遮挡窗口让开。
- 报「没找到名为 X 的应用」→ 按报错里列出的**已安装应用真实名字**挑一个重试；
  列表里没有就说明没装，别再用别的名字反复试。
- 报「已启动 X 但没等到窗口」→ 可能它启动后进了托盘、或弹了要人工处理的登录框，
  也可能是**商店应用的转发壳**（如 System32 的 `calc.exe`）而对应商店应用没装。
  用 `list_windows` 看一眼现状，别盲目加大 timeout 反复重试。
- 连续两次操作失败（目标找不到/坐标无效/界面无变化）就停下来 `ask_user` 澄清，不要盲目重试。

## 安全红线

- 禁止用本插件执行不可逆操作：格式化/分区、删除系统文件、关机/重启/注销、修改系统关键设置、卸载软件，
  除非用户在本次对话中明确要求并已确认；
- 输入密码、支付、验证码等敏感信息前必须先 `ask_user` 让用户自己决定（可提醒用户在 Web UI 上接管自行输入）；
- 操作范围尽量限定在用户指定的目标应用/窗口内，不要顺手改动其他窗口的内容；
- 汇报要如实：没点到的不要声称点到了，拿不准就重新截屏确认。
