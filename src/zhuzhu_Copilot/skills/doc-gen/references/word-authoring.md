# Word 生成 · 深度提示与排版规范

生成 Word/DOCX 前读本文件：先用深度提示词澄清文体与受众，再按结构与排版规范产出，
最后 `read_docx` / `extract_text` 校验、在预览面板查看完整样式。

`assets/examples/示例_完整样式_报告.docx`。

## 1. 深度提示词

```
请为我撰写一份《{标题}》Word 文档，并确认：
1) 文体与用途：通知/公文/合同/报告/方案/论文/培训材料？
2) 受众与立场：对内还是对外、需要正式到什么程度？
3) 篇幅与结构：约多少字、是否需要封面/目录/编号/表格？
4) 素材：数据、图表、品牌/单位抬头、模板或参考文件？
要求：使用规范的标题层级与样式（不要手工放大字号当标题）；
统一字体字号、行距、页边距、编号；表格加表头；必要处配图/图标。
```

**生成指令模板**（变量填全后调用 `create_docx`）：

```
角色：资深{文体}写作专家。输出《{标题}》，受众{受众}，目标{目标}。
结构：{封面/摘要/章节/结论}；约 {字数} 字。
排版：标题用 '# / ## / ###' 层级；正文统一字体字号、1.5 倍行距、
首行缩进（按文体）；页边距规范；章节编号；连续 '|' 行成表并加表头底纹；
插入页码，需要时放 [toc]。语言正式、逻辑清晰、结论先行。
```

## 2. 文体选择（决定格式口径）

- **党政公文/通知**：标题、主送机关、正文、落款日期；字体字号/行距有固定规范。
- **合同/法律文书**：条款化（条/款/项）、定义条款、权利义务、违约责任、签署区。
- **商务报告/方案**：摘要 → 背景 → 分析 → 建议 → 结论；图表支撑。
- **学术论文**：摘要/关键词 → 引言 → 方法 → 结果 → 讨论 → 参考文献。
- **培训材料/手册**：学习目标、分章讲解、案例、要点小结。
- 职场通用：纪要、简报、邮件式说明、制度流程。

## 3. 文档结构

- 长文档：封面 → 目录（`[toc]`）→ 正文章节（多级标题）→ 结论 →
  参考文献/附录；短文档可省封面目录。
- **标题层级清晰且不跳级**（`#` → `##` → `###`），同一层级只表达同一粒度内容。
- 每段一个中心句并放段首；段落 3–6 句；长文用小标题分段。
- 并列要点用 `- ` 项目符号、步骤用 `1. ` 有序列表；强调句用 `> ` 引用块。

## 4. 样式与排版

- **用标记/样式而非手工格式**：标题用 `#` 层级，正文用普通段落，
  便于生成目录、保持统一与后续编辑。
- `style.theme` 按内容气质选（business / warm / tech / red……），正式报告给
  `style.cover={subtitle,author,date}` 生成封面；不要千篇一律。
- 字体：中文正文常用宋体/仿宋（公文）或微软雅黑（现代商务），全篇不超过 2–3 种字体。
- 字号层级固定（正文小四/11–12pt、标题逐级加大加粗）。
- 行距与对齐：正文常用 1.5 倍行距、两端对齐；公文按固定口径；首行缩进按文体。
- 页边距统一、纸张 A4（横向用 `style.page="landscape"`）。
- 强调：**加粗**用于关键结论，斜体/下划线/彩色克制使用。

## 5. 表格 / 图片 / 图标

- 数据对比用**表格**：连续 `| 列 | 列 |` 行成表，表头加底纹、首行加粗、
  数字右对齐、统一小数位与单位。
- 图片用 `images=[路径或{path,align,width}]` 传入，居中、控制宽度（如页宽 80%），
  避免拉伸变形；图文优先“嵌入型”避免错位。
- 需要真实配图用 `generate_image` 生成与主题一致的素材；图标用随附
  `assets/icons/`（star / target / check 等）做章节/要点标识，风格统一。
- 可选文字水印 `style.watermark={text,color}`，倾斜平铺不挡正文。

## 6. 页眉页脚 / 页码 / 目录

- `style.header_text` 设页眉（文档名/单位）；页脚默认居中插入页码。
- 长文档在需要处放 `[toc]`，基于标题层级生成目录；`[pagebreak]` 手动分页。
- 域在纯 Python 生成后可能显示为占位，用 Word 打开更新域即可反映最终结果。

## 7. 读取与编辑已有 Word

- **读取**：`read_docx(path)` 返回结构化 Markdown + meta（paragraphs / styles /
  tables / sections / images），用于理解原稿、定位要改的位置。
- **编辑**：`edit_docx(path, ops=[...])` 以操作数组改稿，常用 op：
  - `replace_text`：全局查找替换（改术语/数字/称谓）。
  - `append_paragraph` / `insert_paragraph`：追加或在指定位置插入段落。
  - `set_heading`：把某段改为指定层级标题。
  - `replace_image` / `delete_paragraph`：换图、删段。
- 编辑返回 `{ok, failed, total}`，失败的 op 按提示修正重试；想保留原稿先复制一份。

## 8. 交付前自检清单

生成或编辑后，先 `read_docx` / `extract_text(path)` 核对，并在预览面板查看，逐项确认：

- [ ] 标题层级正确、无跳级、目录与标题一致
- [ ] 字体/字号/行距/缩进/页边距全篇统一
- [ ] 无文字溢出、无孤行寡行、表格表头底纹正确、未错位
- [ ] 图片清晰不变形、位置正确；图标风格统一
- [ ] 页眉页脚/页码正确；编号正确；中文与特殊符号正常显示
- [ ] 抬头/落款/日期等文体要素齐全（公文/合同场景）
