## 修复 AgentPanel.eventFilter 骨架期 AttributeError（崩溃框）

- 现象：exe 弹崩溃框，栈顶 `agent_panel.py:16888 eventFilter` →
  `AttributeError: 'AgentPanel' object has no attribute 'input'`。
- 根因：`build_default_ui` 在创建输入框（~10649 行 `self.input = _DropTextEdit()`）之前，
  就对顶栏 `status_btn`（~10548 行）调用 `installEventFilter(self)`；
  骨架期该按钮收到 `StyleChange`/`ToolTip` 等事件即进入 `eventFilter`，执行
  `obj is self.input` 时属性尚不存在 → 异常（PyQt6 虚函数内未捕获异常直接弹崩溃框）。
- 修法（`src/winapp_migrator/ui/agent_panel.py`）：`eventFilter` 入口加存在性守卫
  `_inp = getattr(self, "input", None); if _inp is None: return super().eventFilter(obj, event)`，
  并把后续 `obj is self.input` 改为 `obj is _inp`；守卫置于最前，消除对初始化顺序的隐式依赖。
- 测试：新增 `tests/test_agent_panel_event_filter.py`（3 例：骨架期放行 / 就绪后正常透传 /
  Tab 补全分支仍可达）。用 `AgentPanel` 子类只搭 QDialog 壳跳过真实 `__init__`，
  并直接以绑定方式调方法（不经 Qt 虚函数派发，异常才能被 pytest 捕获）。
  反向验证：临时还原旧写法 → 用例 F；恢复后全量 `pytest tests -q` 267 项通过；
  `compileall src mcp_servers` 通过。
- 提交：`0ce7498`。该文件里还有用户大量未提交的在制品，故用 `git apply --cached`
  只把本次这一处修复 + 新测试写入索引，工作区其余改动原样保留。
- 备注：工作区 `.gitignore` / `pytest.ini` / `requirements.txt` 处于被删除状态（用户既有状态，
  未处理；CI 的 `pip install -r requirements.txt` 会因此失败，需要用户确认是否恢复）。

## 修复：对话内切换工作流后主 Agent 身份被共同上下文压制

- 现象：对话内切换工作流后，主 Agent 不按新工作流人设陈述身份，而是顺着共同上下文空间里的
  旧身份/团队口吻回应。
- 根因（已实测复现）：`agent_engine.run()` 把「团队消息」与「共同上下文空间快照」**追加在
  用户提问之后**，成为发给模型的最后一条消息；快照里常含其他成员或上一个工作流的角色自称
  （`- [时间] main（note）：我是产品经理，语气务实`）→ 模型顺从更贴近的文本，压过 system 人设。
  子 Agent 侧本来就是"快照在前、任务目标在最后"（`agent_subagent` 的 `_SHARED_HINT` 路径），
  主引擎与之一致才是对的。
- 修法：
  1. 新增 `AgentEngine._inject_reference_before_user()`：参考性内容一律插到**用户最新一条消息
     之前**（无 user 消息时退化为追加）；run() 里团队消息与共享快照的注入改走该方法。
  2. 新增模块级 `_TEAM_MSG_NOTE` / `_SHARED_SNAPSHOT_NOTE`：身份隔离声明——快照/团队消息中的
     角色自称、称谓、身份、语气描述无论署名为谁（含 main）都不适用于你、不得沿用或模仿，
     身份以系统设定为准，被问及身份时按系统设定回答。
  3. `agent_subagent._SHARED_HINT` 同步补身份约束、团队消息文案复用同一说明（两侧一致）。
- 测试：`tests/test_workflow_identity_switch.py`（5 例）。注意：断言"快照位置"时**不能只搜
  "共同上下文空间"**——不少工作流的人设提示词本身含该词（产品经理工作流要求"加入共同上下文
  空间"），会误命中 system 消息；改用「user 角色 + 【共同上下文空间 表头」定位。
  反向验证：注入顺序改回"追加末尾" → 3 例失败。全量 **322 项通过**，compileall 通过。
- 提交：`168a7fc`（engine + subagent + 新测试；工作区在制品未提交）。
