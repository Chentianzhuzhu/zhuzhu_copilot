## 修复 DeepSeek 网页版桥完成判定（commit dd849f7）

现象：agent 端已停止输出，网页版浏览器还在继续生成；大型任务流（多轮工具调用）无法完成。

根因（agent_web_llm.py WebBridge.ask()）：
1. 完成判定为「文本静止 6 秒」（idle>=12 × 0.5s），长回复 markdown 按块渲染，块间停顿可超 6 秒 → agent 提前收尾，网页版仍在生成。
2. 无「真完成」强信号：DeepSeek 仅在整个回复渲染完成后才挂出消息操作栏（复制/点赞/重新生成），此信号此前完全未利用。
3. 回复出现后 30s 硬截断 → 长回复（含末尾的工具调用 JSON）被截断 → extract_tool_call 解析失败 → 任务流中断。

修复内容：
- 新增 `_GEN_STATE_JS` 页面生成状态检测（DONE/GENERATING/NO_MSG/UNKNOWN），DONE（操作栏出现）立即结束；检测顺序关键：DONE 优先于思考中判定。
- 文本静止兜底阈值 6s → 15s（`_CFG["idle_done_ticks"]`，模块级可配置字典，不硬编码）。
- 移除 30s 硬截断，wait 默认 150 → 240s（总 deadline 兜底）。
- 专家模式思考期（深度思考卡片）文本在非 DONE 时置空，不当作回复输出/流式显示。
- 兜底判定完成后若页面仍 GENERATING → `_click_stop()` 主动点停止按钮，杜绝网页版继续输出。
- `serialize_prompt` 超长裁剪：>24000 字符保留头部（系统指令+工具清单）+ 尾部最近消息，中段截断（防大型任务流多轮历史超网页版输入框上限）。

测试：test_web_llm.py 8 项全过（修正过时断言「工具消息不注入」→ 工具回执注入为有意行为；新增超长裁剪与短 prompt 用例）。

经验：DeepSeek 网页版（新版 DOM）无 button 停止按钮，`button[class*=stop]` 恒 False；完成信号只能依赖「消息操作栏出现」。全局 `[class*="generat"]` 会误匹配「重新生成」按钮（含 generat 子串），不能用。

## 修复 @子Agent 上下文不保留、无法追问（commit 3c00e1d）

现象：@子Agent 直接调用后上下文不保留在主对话中，再次 @同一子 Agent 追问时完全失忆。

根因：`_launch_subagent → _subagent_worker → run_sub_agent`，而 `run_sub_agent` 的 messages 是函数内局部变量，每次调用从零开始（仅 system + goal），结束后历史直接丢弃；会话状态 `_new_sess_state` 无子 Agent 历史字段。

修复：
- `agent_subagent.run_sub_agent` 新增 `history`（注入在 system 后、goal 前）与 `on_history`（finally 中回传完整消息，不含 system，覆盖所有返回路径）；新增 `_sanitize_history`（剔除末尾未配对 assistant(tool_calls)、超长裁剪且保留区首条非 tool）。
- UI `_new_sess_state` 新增 `sub_history`（{子Agent名: 消息列表}）；`_subagent_worker` 读入该子 Agent 历史注入、结束后 `_save` 回写会话状态。
- 持久化链路：`_write_ui_json`/`_persist_current` 落盘 sub_history，`switch_ready` 信号加第 8 参，`_load` 读出、`_finish_switch` 恢复 → 重启/切会话后可继续追问。
- 清空对话（_clear_chat pop 旧 st）自然清除子 Agent 历史；主 Agent 经 dispatch_sub_agents 调子 Agent 仍为一次性任务（不传 history，向后兼容）。

验证：scripts/_verify_subagent_flow.py 全过（事件映射 + 多轮写回/注入 + 真实 run_sub_agent 逻辑 + _sanitize_history）。注意 _verify_batch_fixes.py 第 4 部分 diff 高亮在 offscreen 下失败为既有环境问题，与本次无关。项目 PyQt6 在系统 Python 3.13（AppData\Local\Programs\Python），managed Python 无 PyQt6。
