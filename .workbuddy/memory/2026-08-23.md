## 修复桌宠 GIF 动画（src/winapp_migrator/ui/desktop_pet.py）
需求：鼠标悬停小猫时持续播放 GIF；每 1 分钟自动播一轮完整动画。

修复了三个根因 Bug：
1. `_load_frames` 中 `img.convert("RGBA")` 会破坏 GIF 多帧迭代（72 帧变 1 帧）——改为在原始图像上逐帧 `ImageSequence.Iterator` 后再逐帧转 RGBA。
2. `_load_frames` 中残留死代码 `QImage.fromData(...)` 引用未导入的 `QImage`，触发 NameError 导致加载失败、窗口空白——已删除。
3. 自动播放"播一轮就停"逻辑缺失：`_auto_play_once` 只置 `_playing=True` 永不复位，导致首次触发后无限循环——新增 `_auto_once` 标志，`_advance_frame` 检测回到首帧（next_idx==0）即停止并复位。

另：给 QLabel 加了 `WA_TransparentForMouseEvents`，确保鼠标事件穿透到父窗口，悬停 enter/leave 与拖拽可正常触发。

验证结果：72 帧全部加载；自动模式精确播 72 步后停回首帧；悬停持续播放；离开停止回首帧。时长：每帧 70ms，一轮约 5 秒。

关键经验：
1. **打包必须用系统 Python 3.13**（`C:\Users\zhuzhu\AppData\Local\Programs\Python\Python313\python.exe`，有 PyInstaller 6.20.0 + 全量依赖），不是 workbuddy 管理的 python（无 PyInstaller）。

## 修复 ISCC 未等完导致 Setup.exe 损坏（关键经验）
**根因**：Inno Setup 7.0.0-beta 的 ISCC.exe 是 GUI 子系统程序。用 PowerShell 工具 `Start-Process -Wait`（以及 `&`）**不会真正等它跑完**——ISCC 还在后台压缩 1GB 数据时，PowerShell 工具就提前返回了，产出 88MB/102MB 残缺 Setup.exe，安装时报 "setup files are corrupted"。

**正确做法**：用 Git Bash 直接同步调用 ISCC.exe（MSYS bash 会 waitpid 等待子进程）：
```bash
MSYS_NO_PATHCONV=1 "/c/Program Files/Inno Setup 7/ISCC.exe" "installer/WinAppMigrator.iss" "/DMyAppPwd=Zhutianliang.2026"
```
这样 ISCC 完整跑完（约 185 秒），输出以 "Successful compile" 结尾，Setup.exe 完整 148MB，exit 0。

**判定完整性的标志**：ISCC 输出结尾有 "Successful compile (N sec)"；Setup.exe 完整大小约 148MB（残缺的只有 88~102MB）。桌宠 pet.gif 确认在 `dist/zhuzhu Copilot/_internal/assets/pet.gif`（spec datas 打进 _internal/assets）。

## 修复 AI 面板"无限打开"（重入递归）
**根因**：`main_window._open_agent_panel` 构造 `AgentPanel(self)` 期间，`AgentPanel.__init__` 里 `_build_ui()` 同步卡顿，随后 `QCoreApplication.processEvents()` flush 积压的 clicked 事件；此时 `self._agent_panel` 尚未赋值（`self._agent_panel = AgentPanel(self)` 右边还没执行完），重入的 `_open_agent_panel` 判断 `is None` 为真 → 再次递归 `AgentPanel(self)` → 无限重建，表现为"卡顿时/安装后 AI 面板无限打开"。

**修复**：`_open_agent_panel` 加 `_agent_panel_creating` 防重入锁，构造期间重入直接 return；用 `getattr(self, "_agent_panel", None)` 替代 `hasattr` 判断。已重新打包签名（Setup.exe 148MB，Status=Valid）。

## 修复 hide_main 模式"无限打开"（最终根因）
排查发现用户 QSettings 里 `hide_main_window = 1`（开启"隐藏主窗口，仅显示 AI 面板"），启动时 main.py 会自动 `window._open_agent_panel()` 打开面板。验证：Qt 中 `parent.hide()` **不会**级联隐藏 owned window（实测 isVisible 仍 True），所以 owner 关系本身不是 show/hide 循环的根因。

**最终修复**：hide_main 模式下把 AgentPanel 以 `parent=None` 创建（完全独立顶层窗口），彻底断开与隐藏主窗口的 owned window 关系，避免面板反复显示/隐藏；同时：
1. AgentPanel.__init__ 保存 `self._main_win = parent`；
2. closeEvent/主题挂起/通知等 5 处 `self.parent()` 改为 `getattr(self, "_main_win", None) or self.parent()`（parent=None 时仍能恢复主窗口/发通知）；
3. `_open_agent_panel` 在 hide_main 下 `AgentPanel(None)` 并回填 `_main_win = self`；
4. MainWindow.closeEvent 显式 close AI 面板（parent=None 不会随主窗口自动销毁）。

产物：`dist\zhuzhu Copilot Setup.exe`（148MB）+ 主程序 exe，均已 Authenticode 签名 Valid。

## 修复"无限打开"——真正的根因是子窗口残留
用户截图暴露了真因：桌面上有**多个重复的窗口**（多个 Git 面板 / Bing 预览 / 任务清单 / 小猫咪），不是面板被反复弹出，而是每次启动都残留了一整套窗口。根因：`AgentPanel.closeEvent` 原本只 close 了 `todos_win`，**`git_win` / `wt_win` / `code_win` / 桌宠 全部泄漏**，加上 hide_main 模式下主窗口也隐藏，看起来就像"无限多个窗口"。

修复：closeEvent 改为统一遍历关闭 todos_win / git_win / wt_win / code_win；主窗口 closeEvent 也补齐关闭 AI 面板和桌宠。已重新打包签名。
