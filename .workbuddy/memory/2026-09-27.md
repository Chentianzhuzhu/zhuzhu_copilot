### 关键经验（写代码时要记住）
- `QLabel.heightForWidth()` **已计入 QSS padding**（实测 padding 11/13 → hfw 76 vs 无 padding 54），
  所以可以安全地按 hfw 刚性钉高度。
- 判定"是否已隐藏"要用 `isHidden()`；判定"内容是否变化"要缓存上次测量值 ——
  否则流式每 8ms 一次的调用会把整条消息区反复重排（闪烁 + 掉帧）。
- `QLabel` 默认 `alignment()` = `AlignLeft|AlignVCenter`（129），多余高度会上下均分。
- 面板代理跑集成探针时**不能 `p.show()`**：`resizeEvent` 等覆写会访问未初始化属性，
  PyQt6 未捕获异常直接 abort（表现为"无输出 + 退出码 127"，且 stdout 缓冲丢失）；
  改用 `p.resizeEvent = lambda e: QDialog.resizeEvent(p, e)` 覆盖，或只显示消息区。

## 第三批修复（17:0x，用户反馈"都没解决、闪烁更厉害"）
第一轮修法反而更糟，原因复盘（都记下来避免重犯）：
1. 我在 `_bump_content` 里加了「延迟一帧再钉高度」(`QTimer.singleShot(0, ...)`)——
   120fps 下等于每 8ms 排一个定时器 + 触发一次全量重排，**这就是闪烁加剧的直接原因**。
2. `setMaximumHeight` + `setMinimumHeight` 两次写回 → 布局失效两次；且新文本已 setText
   而上限还是旧值的瞬间会裁切，连续触发 = 闪烁。
3. `_STREAM_TICK_MS=8`（120fps）：实测「一次完整布局+重绘」在流式增长期间约 **5~19ms**，
   8ms 节拍把主线程排满 —— 越"高帧"越卡。已改为 16ms（对齐 60Hz 刷新率，帧间隔均匀
   才是真的丝滑），超大正文 60ms 兜底。
4. **真正的隐藏 bug**：`ChatTurn.heightForWidth` / `relayout_heights` 里用 `isHidden()`
   跳过子块 —— 而**新建控件在父级布局生效前 `isHidden()` 恒为 True**，导致整块正文高度
   被漏算、回合高度停在旧值 → 文字被裁切/底部空白。收起态本来就是「不创建过程控件」，
   这个跳过完全多余，已删除。

当前实现（已验证）：
- `ChatTurn.relayout_heights(width, monotonic)` 是唯一的高度入口：按给定宽度→钉标签最小
  高度→钉块最小高度→钉回合最小高度，**只写最小高度 + 2px 容差**（设上限才有裁切风险），
  生成中 `monotonic=True` 只增不减（markdown 半解析会让换行数回缩）。
- 离屏量测（200 tick 流式，每 tick 走完整事件循环）：回合最小高度 155→2059 **单调递增、
  回退 0 次、±1px 微抖 0 次**；`setMinimumHeight` 平均 0.59 次/tick；完稿后正文标签
  高度 == 内容高度（差 0px）、块高 == 块 hfw、回合仅多 18px（预留的回合底部间距）。
- 新增几何自诊断：`WINAPP_CHAT_DEBUG=1` 启动即把每次渲染的宽度/各块高度/是否写回追加到
  `~/.winapp_migrator/chat_debug.log`（默认关闭零开销）—— 真实窗口下的闪烁类问题靠它定位。
