## 坑：Edit 工具会破坏 agent_panel.py 的 CRLF
- 该文件仓库内是 **CRLF**，Edit 工具编辑后会被规范化成 **LF** → 4.2 万行虚假 diff。
- 而且**外部进程会在写入后把文件改回 LF**（Python 写入后立即读是 CRLF，稍后再读又变
  LF）。裸 Python 转换只在「写入后立刻读取」时看到效果。
- 对策尝试过「改完统一转 CRLF 再立刻 `git add`」：`git add` 确实拿到了 CRLF（`git diff
  --cached` 只有 40 行），但**随后工作区又变回 LF**（`git ls-files --eol` → `w/lf`），
  说明有外部进程在持续规范化。
- **最终处置**（提交 `20deddf`）：把该文件在**仓库里也统一为 LF**（含 `agent_panel.py`
  在内的所有 Python 文件从此都是 LF）。仓库与工作区天然一致，整文件 diff 彻底消失，
  `git status` 干净。**不要再按 CRLF 写这个仓库的文件。**

## 追加（同日第三轮）：回合内区块互相重叠
用户反馈：思考过程气泡、命令执行输出、工具调用输出、正文回复常常叠在一起。

**根因（新探针 `scripts/_probe_turn_layout.py` 定量，合成 25 块的长回合）**：
- 块高只钉了**下界**（`_measure_block` 里的 `setMinimumHeight`），而 QVBoxLayout 会在
  「最小值 < 推荐值 < 最大值」之间做**弹性分配** —— 槽位与实际块高对不上。实测 `cmd`
  块 geometry 占 402px，而下一块只隔 319px，交错重叠 71px，且 y 序列不连续
  （18→184→**300**→…→960→**890**）。先后排除：布局未激活（`invalidate+activate`
  返回 True 仍错）、`setEnabled(False)`（关掉后数值完全相同）、隐藏块干扰（移出布局后
  完全相同）—— 是**确定性**的分配结果。
- 同时回合高度比内部布局真实最小需求少算（实测 3345 vs 3415）：`_more`（「继续显示」）
  的高度从未计入，容器装不下 → 内容溢出。

**修复**：
1. `_measure_block` 改用 `setFixedHeight`（min == max == 本块应有高度）→ 布局只能精确
   分配，展开后逐块几何严格连续（重叠块数 **0**，含收起再展开）。
2. 回合高度以「内部布局真实最小需求」兜底（`_lay_min_h`）：只在全量重排或可见性变化
   （`_lay_min_dirty`）时重算 —— `minimumSize()`/`sizeHint()` 都会遍历全部子项，流式
   每帧无条件调会把单帧成本顶过 `test_frame_cost_is_bounded` 的 4ms 阈值。
   `heightForWidth` 与 `relayout_heights` **必须同口径**（都用 `_lay_min_h`）：一个用
   实时 `_box.sizeHint()`、另一个用缓存值会让包裹层比回合高 35px
   （`test_ai_turn_wrapper` 的「多出量漂移」抓到）。
3. 逐项计账补上 `_more` 高度（此前漏算 24px）。
4. `_PAUSE_LAYOUT_ON_REVEAL` 保持开启（批量 setVisible 期间禁用父布局）—— 固定高度
   保证槽位与块高恒等，禁用期间不会再留下错位。

回归：`test_chat_bubble_demo_parity` 新增 3 例（展开后四类块不重叠、回合高度覆盖布局
最小需求、块高必须 min == max）；全量 799 例通过。

## 追加（同日第四轮）：主题切换后三处异常
用户反馈：切深/浅主题后 ① 文件树内容空白 ② 对话气泡向中间压缩 ③ 面板残留白色/深色元素。

**探针 `scripts/_probe_retheme.py`（跑一遍深↔浅，量几何 + 取像素 + 存截图）定位**：

1. **文件树空白**：`_sync_wt_win` / `_sync_git_win` 只在「原本不可见」时才 `refresh()`
   （避免拖动时反复扫盘），而**重建出的新窗口在 `_build_ui` 里已 show 过** → `isVisible()`
   为真 → 被判为"已可见"而跳过刷新。实测切换后 `treeItems` 由 **1 → 0**。
   修法：`_retheme` 步骤 9 之后对 `wt_win` / `git_win` 各补一次 `refresh()`。
2. **气泡压缩**：`_ai_turn_max_width()` 依赖 `msg_area.viewport().width()`，**重建瞬间视口
   未就绪** → 回退 240px 并被 `setMaximumWidth` 钉死；之后视口变宽也不会自己跟着变
   （实测重建瞬间 maxW=620、稳定后视口只有 361，气泡停在旧值）。注意
   `_bubble_max_width()` 用的是**面板宽度**、不受影响，所以只有 AI 回合会被钉窄。
   修法：`_relayout_messages`（已有自愈路径，被 `_render_history_all` 的 singleShot 触发）
   按**当前**视口重设各气泡最大宽度，宽度未变时不重复 `setMaximumWidth`。
3. **残留深色滚动条**：侧栏控件各自设了样式表（`QTreeWidget` 的底色/选中态等），而 Qt 的
   规则是**控件一旦设有样式表，未显式提及的子控件会退回系统默认外观** —— 滚动条因此在
   所有主题下都是系统深灰（截图确认三处：文件树 / Git / 代码预览；`_scrollbar_css` 用
   的浅色 `BORDER=#E3E8F0` 从未生效）。修法：新增 `AgentPanel._apply_side_scrollbars()`，
   按当前主题给四个侧栏内的滚动区域**追加**（不覆盖、幂等）`_scrollbar_css`，在
   `__init__` 与 `_retheme` 各调一次；顺带给文件树的 `QTreeWidget` 样式表补上滚动条规则。

回归：新增 `tests/test_retheme_refresh.py` 5 例（侧栏滚动条存在/不重复/不覆盖原有规则、
气泡宽度跟随视口、宽度未变不重复 set）；侧栏与气泡的断言都用 `AgentPanel.__new__` 轻代理，

## 壁纸不上屏修复（2026-10-01，提交 3a28785）

用户报"图片无法显示 / 设置新图片没反应 / 设置页设置项被遮挡"。两个真根因：

1. **`_paint_glass_root` 把 `QRectF` 误从 QtGui 导入（实际在 QtCore）** → 每次抛
   ImportError 且被调用方 `except` 吞掉 → 恒返回 False → **壁纸从未上屏**。
   教训：`from PyQt6.QtGui import ...` 写错模块名不会在编译期暴露（py_compile 不查名字），
   只会在运行时抛；而调用方一层 `except Exception` 会把它彻底吞掉。**关键绘制函数
   必须有"返回 True/False"的直接断言测试**，不能只测它调用的底层绘制函数。
2. 面板 paintEvent 的壁纸分支被 `not _panel_frameless()` 挡住：开无边框外壳的用户
   落进旧分支画纯色底。壁纸是否上屏与无边框无关，已解耦（无边框只补边缘高光，
   抽出 `_paint_frameless_edge`）。
3. 正文压在照片上不可读 → 新增 `root_veil_color()` 磨砂纱（壁纸平均色 + alpha=
   地板0.42+frost×0.34）。**刻意不乘 opacity**：这层是可读性地板，乘上去用户调低
   透明度正文就重新压回照片。
4. `wallpaper_ok()` 以「能解码出位图」为准（文件存在 ≠ 能显示）；
   `import_background` 收编前先 QPixmap 解码验证 + 清理旧扩展名残留。

另：设置页有无边框模式下可用的自绘标题栏 `_frameless_titlebar`，不要假设它没有。
