## 本次补齐的缺口
1. **并发计数竞争**：`agent_tools._record_edit_delta` 的 `d["added"] += ...` 为非原子读改写，
   并发写多文件会丢计数 → 新增模块级 `_EDIT_DELTA_LOCK`，diff 计算在锁外、仅累加加锁。
2. **并发范围扩展**：原仅 3 个写工具并发（且漏了 `insert_lines`）。改为两类常量：
   - `_CONCURRENT_WRITE_TOOLS`（write/edit/search_replace/insert_lines）→ 同路径加锁
   - `_CONCURRENT_READ_TOOLS`（read_file/list_directory/search_files/grep/search_code/
     find_app/extract_text/system_info/get_time/env_var/git_info/web_search）→ 直接并行
   - 新增 `AgentEngine._run_one_tool()` 作为线程池 worker 入口（绑定变更桶 + 按类加锁）
   - 常量 `_CONCURRENT_EDIT_MAX_WORKERS` → `_CONCURRENT_MAX_WORKERS`
   - **`web_fetch` 刻意不并发**：其失败回退会启动独立 headless 浏览器（无全局限流），
     并发会拉起多个浏览器进程反而更慢。
3. **关键架构性质**：`on_result`/`on_preview` 始终在**串行收尾循环按原始调用顺序**触发，
   并发只改变执行耗时，不改对话展示与上下文落库顺序（改造时务必保持这一点）。

## 教训（可复用）
- **性能断言不要用绝对耗时**：原 `el < 0.4*3-0.2` 把引擎每轮固定开销（工具集/系统提示构建
  ~0.5s）算进去了，实测并发本该 0.5s 却偶发 1.0~1.2s 而 flaky。
  改用「并发耗时 / 串行耗时」比值（阈值 0.7）+ 任务数 > 线程上限（8 个任务 / 4 worker）。
- 并发 bug 定位法：在 worker 入口打时间戳 → 确认是否并发进入；再在 `_execute` 内层打点 →
  确认耗时归属。本次据此证明并发正常、慢在引擎固定开销。
- 诊断 print 一律用 `import sys as _sys; print(..., file=_sys.stderr, flush=True)`，
  验证完必须清理（grep 复查）。

# 2026-09-26（第二段）共同上下文空间「对话隔离」

## 需求
「每个对话之间隔离共享上文空间，仅同一对话之间的 agent 开启共享上文空间」。

## 根因（旧设计只有「空间」一维）
`agent_context` 是进程级单例：`DEFAULT_SPACE="default"` 单一全局桶 + `_active` 单一
全局活跃空间。后果三条：
1. 对话 A 激活团队 → `_active="default"`；切到对话 B，`bind_shared_context` 的
   回退链（space → `current()` → DEFAULT_SPACE）让 B 的 agent 读到 A 的快照、写进 A 的空间。
2. 引擎自动开空间（`open_space(seed, owner="main", activate=True)`）不区分对话。
3. `team_stop_all()` 无过滤：A 对话停止任务会停掉 B 对话的后台成员。

## 改法（关键决策）
在 `agent_context` 增加**对话维度**，物理键 = `<conversation>::<逻辑空间 id>`：
- `set_conversation`（线程局部）/ `set_conversation_global`（UI 主线程）/
  `current_conversation()` = 线程局部 > 全局 > 空；`scoped()` 做归一化且**幂等**
  （已是物理键原样返回，故可安全跨线程传递）；`open_space` 返回**逻辑 id**，
  会话落盘/UI 复用不受影响；`_active` 改为 `{对话: 逻辑 id}`；新增
  `close_conversation()`（删对话回收）、`list_spaces(all_conversations=False)`。
- **无当前对话时行为与旧版完全一致** —— 这是让 28 个既有共享空间测试零改动通过的关键。
- 线程边界必须**显式下传**对话（线程池线程/新建线程无继承的线程局部）：
  `dispatch_sub_agents` 在父线程捕获一次 → `run_sub_agent`；
  `run_agent_llm`/`dispatch_agent_llm`/`team_start`/`_run_loop` 同理；
  `AgentEngine(conversation=sid)` 在 `run()` 里落地（**必须在 on_task_start 钩子之前**，
  否则工作团激活时开的是上个对话的空间）并在 finally 复位；`AgentPanel._bind_sess`
  设全局对话（唯一收口点，7 处绑定调用全覆盖）。

## 测试

`_active` 按对话、list/stats/close 过滤、同对话共享+跨对话互不可见、线程池下传、

## 追加：打字指示器状态随动作同步（提交 8db3df7）
用户要求：搜索文件 / 操作浏览器 / 获取时间 / 轮询命令 / 等待命令 / **回复普通正文**
时，转圈行都要同步显示对应状态。

**根因（四条，全部真实存在）**
1. **并发路径吞掉单工具文案**：并发集合内的工具（search_files、get_time、read_file…）
   在并发阶段执行，串行收尾循环跳过 `正在执行: <name>`，转圈行只显示
   「正在并行执行 1 个工具调用（<名>）」—— 用户看到的就是这个，而非「正在搜索文件」。
2. **正文回复期间文案冻结**：`_on_delta` 只调 `_finish_thinking()`（置「已思考 N 秒」），
   整个流式正文期间不变。
3. **「待执行工具:」不更新文案**：预处理阶段（技能拦截/参数校验/**用户确认弹窗**）
   可能长时间停留，文案仍是上一状态。
4. **映射覆盖不足**：90 个工具中 38 个落「正在调用工具 <名>」回退
   （browser_tabs/browser_switch_tab/search_large/explore_project/pause_agent…）。

**改法**
- 映射改**三层查找**：精确 `_OP_STATUS` → 族兜底（`_OP_FAMILY_PREFIX` 前缀族 +
  `_OP_FAMILY_KEYWORD` 关键词族）→ 回退。新增工具自动落到所属族描述
  （新增 browser_xxx → 「正在操作浏览器」），**无需改表**；覆盖度 52/90 → **90/90**。
  族顺序：前缀族先于关键词族（`create_mcp` → 前缀 `create_` 命中「正在创建」）。
- 新增常量 `_OP_STATUS_REPLY = "正在回复正文"`，`_on_delta` 内同步转圈行。
- `待执行工具:` 分支加 `_set_spinner_text(_op_status_text(name))`。
- **引擎侧按数量区分**：`len(_jobs) == 1` 发 `正在执行: <工具>`（走精准文案），
  多个才发「正在并行执行 N 个工具调用（…）」。

**新坑：技能规范化拦截会少一条调用**
`tests/test_tool_enhance_concurrent.py` 的「3 个 read_file 并发」断言起初失败
（实际只报 2 个）—— 原因是**技能规范化拦截**会把本轮**首个**被技能覆盖的调用拦下
（注入规范后让模型重发），该调用不进 `pending`。已在 `_make_engine` 里 patch
`agent_skills.skills_covering_tools` 返回 `{}` 彻底隔离（与 `_DEV_TOOLS` 同理）。
**凡断言「同一轮 N 个工具」的用例，都必须先隔离这两个机制。**

**测试**：UI 侧 +7 项（六类动作文案 / 族兜底 / 「全部已注册工具必须有具体文案」的扩展性
守卫 / 两个同步点），引擎侧 +2 项（单个走精准、多个走批次）。反向验证：去掉
`_on_delta` 正文状态 → `assert '' == '正在回复正文'`；去掉单工具分支 → 复现
「正在并行执行 1 个工具调用（search_files）」。本文件 28 项 + UI/引擎子集 62 项通过。

## 两个核心 BUG 的根因（离屏复现确认）
1. **生成中切深浅色主题报错+气泡清空成条状**：`_retheme` 重建 UI 后
   `self._spinner_row` 仍指向已销毁的旧 QVBoxLayout，`_render_history_all →
   _add_bubble → _place_spinner_bottom` 对死布局 `insertLayout` 抛
   RuntimeError，整条消息流渲染中途夭折。修法三处：
   `_retheme` 重建后清 `_spinner/_spinner_lbl/_spinner_row/_compact_row` 悬空引用
   并补 `_sync_task_ui()`；`_ensure_spinner` 仿 `_ensure_compact_row` 校验行仍在布局；
   `_place_spinner_bottom` try/except RuntimeError 安全清理。

   加 try/except RuntimeError。
