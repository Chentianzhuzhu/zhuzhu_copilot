## 追加二：动画改为「整个窗口由粒子生成」（60fps）
- 用户澄清：要的是**整体面板粒子渐变生成完整窗口**，而不是先弹出空窗口再显示里面内容。
- 方案切换：由"面板同色遮罩覆盖未生成区"改为**逐帧推进窗口掩码**
  （`CopilotPanel.apply_reveal(progress)` → `setMask(QRegion(0,0,w,h*progress))`，
  未生成部分真正透明；前沿叠加一组稳定的粒子侵蚀分块，边界呈颗粒状）。
- 关键坑：`SetWindowRgn`（`apply_rounded_window`）与 `setMask` 是同一套窗口区域机制，
  **互斥** → 用 `_reveal_pending` 标志抑制 `showEvent`/`resizeEvent` 里的圆角设置，
  结束时 `finish_reveal()` 再 `clearMask()` + 恢复圆角。
- 60fps：`Qt.TimerType.PreciseTimer` + `setInterval(16)`（默认 ±5% 精度会拖成约 20ms）；
  进度由 `time.monotonic()` 插值（帧率无关）+ 轻微缓出 `1-(1-p)^2`。
  弹出不再做窗口级 alpha 淡入（那正是"先出现空窗口"的来源），起手 `setMask(空)`。
- 测试陷阱：单调时钟驱动的动画，首次 `processEvents()` 会阻塞数百毫秒 → 动画一步跑完，
  中间态观测不到（曾读到掩码高度 0 误判为 bug）。改为直接按 p 调 `apply_reveal()`
  断言掩码包围盒单调增长（实测 10 → 212 → 415 → 584），另加"完整播放后掩码撤销"用例。
- 测试：`test_copilot_panel` 15 项；探针 [6] 段扩到 7 项检查；全量回归 373 passed。

## 追加四：官网「空白+只剩一张图 / CSS/JS 失效」故障定位（根因在 Cloudflare）
- 现象：用户访问 https://chentian.dpdns.org 只见一张空图片，CSS/JS 均报错。
- 定位结论：**源站与代码完全正常，全部现象由 Cloudflare 全站质询引起**，且早于本次改版就已存在。
  - 源站 `127.0.0.1:8080`：`/` text/html 200、`/css/site.css` text/css 200、`/js/site.js` text/javascript 200，MIME 正确。
  - 域名：`403 + Server: cloudflare + Cf-Mitigated: challenge`；真浏览器内核（Edge --dump-dom）同样拿到「请稍候…」页。
  - 质询页只有一个内联 SVG 图标 → 对应"空空的一张图片"；CSS/JS 请求也返回质询页 HTML。
  - **指纹**：`robots.txt` 正常放行、其他路径（含静态资源）全 403 —— Cloudflare 对 robots.txt 有特殊放行。
- 用户处置：自行关闭 Cloudflare 的「I'm Under Attack」模式（本次不改代码、不改 nginx）。
- 两个硬约束（已写入 update-server/README.md §7 与技能）：
  1. 源站证书是 Cloudflare Origin CA 签发，浏览器不信任 → **不能靠「DNS 改灰云」绕过质询**，除非先换受信任证书。
  2. nginx `default_server` 是 `return 444`（防 IP 直连）→ 裸 IP 返回 000；要临时旁路必须新增 server 块，
     属于安全态势变更，**必须先问用户**。

## 追加五：官网线上故障连环排查（CF 质询 / 资源 404 / 弹层遮罩 / 后台相对路径）
按用户反馈顺序记录，都是"线上能用眼睛看到、而代码看着没问题"的坑：
1. **整屏空白 + 只有一张图标** → Cloudflare 全站质询（早于本次改版就存在）。
   指纹：`robots.txt` 正常、其他路径（含 CSS/JS）全 403。用户关掉 Under Attack 后恢复。
2. **图标/照片异常大** → 样式没生效。原因是 15:05–15:07 那次我部署的资源处理器 bug
   让带 `?v=` 的 CSS 短暂 404，而 **404 按 HTTP 规范可被缓存**；修复后 URL 未变 → 浏览器一直用坏响应。
   根治：`AssetVersionService` 的版本号从「内容哈希」升级为「内容哈希-部署标识（jar mtime）」，
   每次部署 URL 必变，客户端自动脱离坏缓存，不需要用户清缓存。
3. **黑色空白弹窗关不掉** → `.lightbox` / `.video-modal` 带 `hidden` 属性，但样式里写了 `display: flex`；
   **作者样式的 display 会盖掉浏览器默认的 `[hidden]{display:none}`**，于是弹层常显、关闭无效。
   修复：`site.css` 增加全局 `[hidden] { display: none !important; }`。
   教训：这类问题 DOM 检查与单元测试都发现不了，必须真的渲染出来看（沙箱内 Edge 可 `--screenshot`，
   再用 PIL 做亮度/分区分析或字符亮度图"看"布局；`--dump-dom` 只验证脚本是否执行）。
4. **后台 CSS/JS 无效** → `/admin` 是**内部转发**，浏览器地址栏仍是 `/admin`，
   而页面写的是相对路径 `href="admin.css"` → 请求 `/admin.css` → 404。
   修复：后台资源一律绝对路径；并补 `/admin/` 入口。
5. **媒体库上传后官网不同步** → 媒体库只是资源仓库，官网显示由「内容管理」的列表决定；
   顺带发现用户删掉旧主视觉图后 `heroImage` 仍指向它 → 首页 404 空图（已置空并回退到实时数据面板）。
   后台补：删除媒体时提示"仍被哪些位置引用"。
6. 部署脚本 `tools/deploy.py` 新增**通用体检**：后台 5 条路由 + 「页面引用的站内资源必须可取」
   （按浏览器规则解析相对路径逐个真请求）。第 2、4 条都属于这一类，现在会被自动拦住。
- 期间还发现**有另一处会话在并行修改同一批文件**（14:34 出现我未写过的 `initVisibilityFallback`、
  15:0x 出现 `AssetVersionService`），并有半成品导致线上 404。改动我先按当前最终状态统一校验再部署，
  但**并发部署同一台服务器有相互覆盖的风险**，值得提醒用户。
