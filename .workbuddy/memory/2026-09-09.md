## 修复 agnes-ai 上游 HTTP 400：create_xlsx 工具 schema 非法

**现象**：chat_stream 请求被上游 `https://api.agnes-ai.cn/v1/chat/completions` 拒绝（HTTP 400），报 `Tool 42 function has invalid 'parameters' schema: ['name', 'rows'] is not of type 'object', 'boolean'`，路径指向 `properties.sheets.items.properties.required`。

**根因**：`src/zhuzhu_Copilot/core/agent_tools.py` 中 create_xlsx 工具的 `sheets.items` 定义里，`format` 子对象的大括号闭合错位（`}}},` 少闭一层），导致 `"required": ["name", "rows"]` 被嵌进 `items.properties` 内部成为名为 required 的"属性"（值为数组，非法 schema）。OpenAI 兼容上游按 JSON Schema Draft 2020-12 metaschema 严格校验工具定义，一个工具非法即拒绝整包 80 个工具的请求。

**修复**：第 1147 行 `}}},` → `}}}},`、第 1148 行 `}}}` → `}}`，将 required 移回 items 级（properties 的兄弟节点）。仅 2 行改动。

**验证**：
- 结构自检：全 80 个工具无 required 误嵌 properties 的情况
- `jsonschema.Draft202012Validator.check_schema`：全部 80 个工具通过元校验
- 已单独提交 commit `b16067f`（工作区其他未提交改动未动）

**排查技巧（可复用）**：这类"上游 400 schema 非法"报错，报错路径就是字典路径，直接 import 模块后编程式遍历 TOOLS 验证，比肉眼数大括号可靠。深层嵌套 dict 字面量定义工具 schema 时，`required` 与 `properties` 必须同级，格式化对齐也难防错位。

## 修复任务栏图标显示默认 python 图标

**现象**：源码运行 `python src/main.py`，Windows 任务栏按钮图标显示为 `python.exe` 默认图标而非应用专属小猪图。

**根因**：
1. `assets/icon.ico` 当时只有 1 帧 256×256 PNG（被某次单图覆盖，丢失了原 `generate_icon.py` 设计的 16/24/32/48/64/128/256 多帧结构）。
2. `src/zhuzhu_Copilot/utils/helpers.py::set_native_window_icon` 用 `LoadImageW` 请求 32×32（大图标/任务栏）与 16×16（小图标/标题栏），当 .ico 内没有恰好匹配尺寸的帧时 `LoadImageW` 对 PNG 压缩帧返回 NULL；`WM_SETICON` 从未真正发送，Explorer 回退取 python.exe 进程图标。
3. 附加缺陷：每次 `showEvent` 都 `LoadImageW` 新 HICON 且从不 `DestroyIcon`，反复 hide/show（托盘还原、隐藏主窗口模式）会持续泄漏 GDI 句柄。

**修复**：
1. 提取原 256 PNG 主图，`LANCZOS` 高质量下采样重建 16/24/32/48/64/128/256 共 7 帧的多帧 ICO（保留视觉）。`assets/icon.ico` 由 6886B → 24279B。
2. `set_native_window_icon` 新增句柄跟踪：每次 SendMessage 设置新句柄后 `DestroyIcon` 上一轮句柄，跟踪挂 `widget._native_icon_big/_small`。
3. 备份 `assets/icon.ico.bak` 移出 assets 目录（防止 PyInstaller datas 把它打进安装包），临时脚本与源 PNG 留在 `.workbuddy/`（git 忽略）。

**验证**：
- ico dir entries: 7（全部 PNG，`LoadImageW(32,32)` 与 `(16,16)` 直接命中精确位图）。
- `helpers.py` AST 解析通过。
- 单独提交 commit `85c12cf`，仅 2 文件改动，未触碰工作区其他未提交改动。

**经验（可复用）**：
- Windows 应用图标必须是多帧 ICO（16/24/32/48/64/128/256），单帧 256 PNG 在任务栏/标题栏渲染会失败或回退。
- `LoadImageW` 对 PNG 压缩帧不进行尺寸缩放，文件内必须有精确尺寸帧才能命中。
- 跨 Qt 与 Win32 设置图标后，HICON 生命周期必须自己管理，Qt 不会代为 DestroyIcon。

## 修复 ask 提问崩溃:TypeError unhashable type 'list'（commit 243fd62）

**现象**：AI 提问（ask_user）时 `_apply_refresh_ai_html → _build_ai_html → _seg_cache.get(sig)` 抛 `TypeError: unhashable type: 'list'`。
**根因**：`_seg_sig` 的 ask 分支把 `options`（list）原样放进签名元组 → 元组含 list 不可哈希；带选项的提问（options 非空）必现，纯文本提问无选项因此未触发。
**修复**：签名中 `options` 归一为 tuple（`tuple(opts) if isinstance(opts,list) else opts`），保持 answer 回填后签名变化、强制重渲染的缓存语义。
**教训（可复用）**：凡加入 `_seg_sig` 的分段字段必须整体可哈希（字符串/int/bool/tuple），dict/list 一律先转 tuple，否则 `_seg_cache.get(sig)` 在运行期抛 TypeError。

## 修复 AI 文件变更行数不显示：新建文件伪 -1 红行 + 编辑徽章不显示（commit 6e12d85）

**用户报修**：AI 创建新文件时"+N"行数未显示变更样式，编辑现有文件时变更行数都显示不了。

**根因 1（agent_panel._build_diff_lines 伪删除行）**：
`(old_text or "").splitlines() or [""]` 在空文本时塞一个空行占位，SequenceMatcher 把那行空串判为删除段。新文件 `old_text=""` → diff 恒定出现 1 行 `-`、首行 first=0、整行被染成红色背景、标题 `-1`（红）+ `+N`（绿）。写新文件后用户看到一条本不该有的红色"删除空行"。

**根因 2（agent_engine 跨线程桶不绑定 → 气泡末尾 -N/+M 徽章全无）**：
工具在 `_call_with_stop` 派生的 worker 线程执行，reset_edit_delta 写入的是 run 线程的 thread-local，worker 线程 `_EDIT_DELTA.d` 为 None → `_record_edit_delta` 直接 return → `_last_edit_delta` 永远 0/0 → `_add_change_badge` 拿到空 dict，不显示。工作区里已有 `_with_edit_bucket` 包装但三处 `_call_with_stop` 都未套上（残缺修复）。

**修复**：
1. `_build_diff_lines`：去掉 `or [""]` 兜底；空文本就当 `[]`，差分器在两侧都空时无 opcodes、单侧空时输出纯 insert/delete，无伪行。
2. `agent_tools.reset_edit_delta()` 改为返回累计桶 dict；新增 `bind_edit_bucket(bucket)` 把指定桶发布到当前线程。
3. `agent_engine`：新增 `self._edit_bucket` 实例属性 + `_with_edit_bucket(fn)` 包装；三处 `_call_with_stop`（subagent 705 / 内置工具 718-723 / MCP 770）lambda 改套 `self._with_edit_bucket`；`run()` 起始从 `reset_edit_delta()` 拿桶、终从 `self._edit_bucket` 读快照挂到 `_last_edit_delta`。

**验证**：
- `_build_diff_lines` 8 场景全过：新建/全删/编辑替换/无变化/空双侧/无尾换行
- 跨线程 `bind_edit_bucket` 共享桶 + 模拟引擎 `run()` 模式累加：单元测试通过
- `scripts/_verify_delta_e2e.py` 全链路：write_file 新建 → `files[新文件]=[4,0]`、edit_file b→X\nY → `files[旧文件]=[2,1]`、整体 `+6 -1`
- `py -3.13 -m pytest tests/` 全套 75 项通过
- 提交 `6e12d85`，工作区其他未提交改动（input_guard/update_check/_verify_diff_scroll/_verify_replay_sync）未触碰

**排查技巧（可复用）**：
- 跨线程 thread-local 失效是经典坑：reset 与 record 必须在同一线程；如必须跨线程，须用一个跨线程共享的 dict（如本例的 `_edit_bucket`）+ 每个 worker 入口 bind。
- difflib 的"占位行"易引入伪 diff：空序列就当 `[]`，别塞占位行；想表示"无内容"让差分器自己决定。
- 测试脚本里的 monkey-patch 包装若不 `return _orig()` 会偷偷吞返回值（这次 `_dbg_reset` 漏 return 让 `_edit_bucket` 变 None，掩盖了真正的 bind 修复 → 务必让包装 return 原函数返回值）。
